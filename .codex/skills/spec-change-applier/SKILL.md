# Spec Change Applier

명시적으로 승인된 변경 제안만 공식 로컬 스펙에 반영한다. 승인 범위를
넘기지 않고, 미결정 내용을 확정하지 않으며, 반영 결과가 다시 읽어도
일관된 경우에만 제안을 완료 처리한다.

## 실행 조건

다음을 모두 확인한다.

1. 사용자가 변경 제안을 명시적으로 승인했다.
2. 반영할 `docs/spec-changes/pending/*.md` 파일이 특정되었다.
3. 승인이 제안 전체인지 일부인지 확인되었다.
4. 승인 문구와 제안 내용이 서로 모순되지 않는다.

하나라도 확인되지 않으면 공식 스펙을 수정하지 않고 부족한 승인 증거를
보고한다.

## 변경 범위

수정할 수 있는 대상:

- 승인 범위와 직접 관련된 `docs/specs/domains/*.md`
- 필요한 `docs/specs/COMMON.md`
- 필요한 `docs/specs/contracts/API.md`
- 필요한 `docs/specs/contracts/DATA_MODEL.md`
- 화면 이동이 바뀐 경우 `docs/specs/UI_AND_NAVIGATION.md`
- 영향 매핑인 `docs/specs/COVERAGE.md`
- 라우팅이 바뀐 경우에만 `docs/specs/INDEX.md`
- 지정된 변경 제안 파일과, 완료 시 해당 파일의 `applied/` 이동

수정하지 않는 대상:

- 소스 코드, 테스트, 빌드 설정
- 승인되지 않은 다른 스펙과 제안
- Notion 또는 외부 문서
- 실제 존재가 확인되지 않은 커밋 정보

## 1. 승인과 제안 확인

1. 현재 사용자 승인 문구와 지정된 `pending` 파일을 읽는다.
2. 제안의 상태, 기존 내용, 제안 내용, 영향 범위, 질문을 확인한다.
3. `applied/`에서 같은 제안이 이미 처리됐는지 확인한다.
4. 전체 승인과 일부 승인을 구분해 적용할 문장을 목록으로 고정한다.
5. 승인되지 않은 내용과 미결정 질문은 적용 목록에서 제외한다.

이미 적용된 제안이면 재반영하지 않고 현재 공식 스펙의 반영 상태만
보고한다.

## 2. 필요한 스펙만 읽기

다음 순서로 필요한 문서만 읽는다.

```text
INDEX.md
→ 관련 도메인의 AI 작업 컨텍스트
→ 필요한 본문
→ 직접 관련된 COMMON/API/DATA_MODEL/UI 계약
```

`COVERAGE.md`는 승인된 변경의 원본 매핑과 반영 문서를 확인하기 위해
읽는다. 모든 도메인 스펙을 한 번에 읽지 않는다.

## 3. 승인된 범위 반영

1. 승인된 내용만 관련 도메인 스펙에 반영한다.
2. API·데이터·인증·권한 변경이면 관련 로컬 계약을 함께 갱신한다.
3. 화면 진입이나 이동이 바뀌면 `UI_AND_NAVIGATION.md`를 갱신한다.
4. 영향받은 원본 매핑과 상태를 `COVERAGE.md`에 갱신한다.
5. 작업 영역의 라우팅이 달라진 경우에만 `INDEX.md`를 갱신한다.
6. 승인 범위를 넓혀 주변 기능을 정리하지 않는다.
7. 미결정 사항을 확정 규칙이나 인수 조건으로 옮기지 않는다.

일부 승인에서는 승인된 부분만 반영한다. 나머지 내용의 승인·보류·반려가
확정되지 않았다면 제안을 `pending/`에 남기고 `결정 및 반영`에 부분
반영 범위를 기록한다. 처리 범위 전체의 처분이 끝난 경우에만
`applied/`로 이동한다.

## 4. 검증

변경된 문서를 모두 다시 읽고 다음을 확인한다.

- 승인된 내용이 정확히 반영되었다.
- 승인되지 않은 내용은 공식 스펙에 들어가지 않았다.
- 도메인과 API·데이터·권한·UI 계약이 서로 모순되지 않는다.
- `COVERAGE.md`의 영향 행이 현재 반영 위치를 가리킨다.
- 라우팅이 바뀌지 않았다면 `INDEX.md`가 불필요하게 수정되지 않았다.
- 로컬 링크가 유효하다.
- 소스 코드, 테스트, 빌드 설정이 변경되지 않았다.

검증에 실패하면 제안을 `applied/`로 이동하지 않는다.

## 5. 제안 기록과 이동

제안의 `결정 및 반영`에 확인된 정보만 기록한다.

- 결정: 승인, 일부 승인, 보류 또는 반려와 승인 범위
- 결정자: 실제로 확인된 경우
- 결정일: 실제로 확인된 경우
- 반영 문서: 실제 수정한 로컬 문서
- 반영 커밋: 실제 커밋이 확인된 경우에만 기록

전체 처리가 끝나고 검증을 통과한 제안만 동일한 파일명으로
`docs/spec-changes/applied/`에 이동한다. 기존 파일을 덮어쓰지 않는다.

## 6. 결과 보고

```text
승인 범위: 전체 | 일부 | 확인 불가
반영 제안: pending 경로
수정 문서: 실제 수정 경로
계약 동기화: API | DATA_MODEL | COMMON | UI | 없음
COVERAGE: 갱신 | 변경 없음
INDEX: 갱신 | 라우팅 변경 없음
제안 상태: applied 이동 | pending 유지 | 변경 없음
검증: 통과 | 실패와 이유
```
