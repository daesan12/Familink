# KDT Retrospective Capture

작업 흐름을 방해하지 않으면서 나중에 KPT 또는 Lessons Learned로 다듬을 가치가 있는 사건만
개인 로컬 메모에 남긴다. 이 기록은 공식 문서가 아니라 후보 자료이므로 짧고 사실 중심이어야 한다.

## 실행 경계

이 스킬은 다음 결과만 만든다.

1. 현재 작업자를 안전하게 식별한다.
2. 방금 발생한 사건이 회고 기준을 충족하는지 판단한다.
3. 민감정보와 사람에 대한 평가를 제거한다.
4. 한국 시간 기준 개인별 날짜 파일에 한 항목을 생성하거나 보완한다.
5. 대상 파일이 Git에서 제외되는지 확인한다.

Jira, Notion, Confluence, 공식 스펙, 제품 코드, Git 이력은 수정하지 않는다. 회고 메모를 stage,
commit 또는 push하지 않는다. 최종 KPT 반영은 사람이 선별하는 별도 작업이다.

## 2. 회고 가치 판정

아래 중 하나 이상이 관찰된 사실로 확인될 때 기록한다.

- **Keep**: 품질이나 속도를 실제로 높였고 다음 작업에서도 반복할 만한 방법
- **Problem**: 예상하지 못한 실패, 잘못된 가정, 누락된 계약, 반복될 가능성이 있는 장애
- **Try**: 위 문제를 다음 작업에서 예방할 수 있는 구체적이고 실행 가능한 변화
- **Learned**: 문서나 코드만 훑어서는 알기 어려웠던 기술·도구·프로세스의 재사용 가능한 교훈
- 테스트, 빌드, 정적 분석, 리뷰가 실제 결함이나 잘못된 전제를 발견한 경우
- 스펙과 구현, 도구 설명과 실제 환경, 담당 경계 사이의 충돌을 확인하고 해결한 경우
- 동일한 실수를 두 번 이상 겪어 재발 방지 규칙을 마련한 경우

다음은 기록하지 않는다.

- 파일 읽기, 검색, 정상 빌드처럼 일상적인 작업 진행
- 아직 원인이 확인되지 않은 추측이나 임시 가설
- 사용자에게 이미 단순 상태 보고로 충분한 내용
- 결과에 영향을 주지 않은 사소한 명령 오타
- 개인 성과 평가, 책임 추궁, 감정적 표현

판단이 애매하면 기록하지 않는다. 회고 후보 수보다 신호의 품질을 우선한다.

## 3. 안전하게 요약

기록 전 다음 내용을 제거하거나 일반화한다.

- 토큰, 비밀번호, 쿠키, 개인키, `.env` 값과 내부 접속 정보
- 실사용자 개인정보와 테스트에 불필요한 이메일
- 팀원에 대한 평가나 비난
- 확인되지 않은 원인과 과장된 성과

명령이나 오류가 근거로 필요하면 비밀값을 `[REDACTED]`로 바꾸고 핵심 한 줄만 남긴다.
사람이 아니라 조건, 과정, 시스템 동작을 주어로 쓴다.

## 4. 날짜 파일에 기록

한국 시간 `Asia/Seoul`의 오늘 날짜를 `YYYY-MM-DD`로 구한다. 대상은
`kdt-retrospectives/<작업자>/YYYY-MM-DD.md`이다. 작업자 디렉터리가 없으면 생성한다.

파일이 없으면 다음 머리말로 시작한다.

```markdown
# YYYY-MM-DD KDT 회고 후보

> 자동 수집된 개인 로컬 메모입니다. 최종 회고 반영 전 사실과 표현을 다시 검토합니다.
```

각 사건은 다음 형식을 사용한다.

```markdown
## HH:mm · [Keep|Problem|Try|Learned] 짧은 제목

- 작업: `Jira 키 또는 브랜치`, 없으면 `일반 작업`
- 사실: 실제로 관찰하고 확인한 사건
- 영향: 작업 결과나 다음 작업에 중요한 이유
- 배운 점: 다른 작업에도 적용할 수 있는 교훈
- 다음 행동: 구체적인 예방·반복 행동, 없으면 `없음`
- 근거: 파일 경로, 테스트명, 명령 결과 또는 오류의 비밀 제거 요약
```

한 사건이 여러 범주에 걸치면 가장 핵심적인 범주 하나를 제목에 사용하고 나머지는 본문에 녹인다.
제목은 결과를 드러내며 `문제 발생`, `작업 완료`처럼 모호하게 쓰지 않는다.

## 5. 중복을 방지하고 기존 메모를 보완

쓰기 전에 오늘 파일을 읽는다.

- 같은 작업·같은 원인·같은 교훈이 이미 있으면 새 항목을 추가하지 않는다.
- 기존 항목이 가설이고 이후 원인이 확인되었다면 해당 항목만 최소 수정한다.
- 한 작업에서 연속된 증상과 해결은 가능한 한 하나의 사건으로 합친다.
- 서로 독립적인 교훈만 별도 항목으로 분리한다.

자동 수집 때문에 작업마다 한 줄씩 쌓이는 로그가 되지 않도록 한다.

## 6. Git 제외 검증

기록 후 다음과 동등한 읽기 전용 검사를 수행한다.

```powershell
git check-ignore -v -- "kdt-retrospectives/<작업자>/YYYY-MM-DD.md"
git status --short -- "kdt-retrospectives/"
```

첫 검사는 `.gitignore` 규칙을 보여야 하고 두 번째 검사는 아무 항목도 보여서는 안 된다.
검증에 실패하면 추가 기록을 중단하고 사용자에게 경로가 Git에 노출될 수 있다고 알린다.

## 작업 종료 시 동작

작업 도중 기준을 충족한 사건이 생기면 해결과 검증이 끝난 시점에 기록한다. 작업 종료 전에는
누락된 후보가 있는지 한 번만 점검한다. 기록할 사건이 없으면 파일을 만들지 않고, 회고가 없다는
사실도 별도 보고하지 않는다.

기록한 경우 최종 응답에는 개인 로컬 회고 후보를 몇 건 남겼는지만 짧게 알린다. 내용 전체를
반복하지 않는다.
