# [FEED_AND_MEDIA] 피드·미디어·게시글 분석

> 상태: 일부 확정
> 기준: 2026-07-27, API 명세서 2차 수정본

## AI 작업 컨텍스트

- 목적: 그룹 구성원이 게시글과 미디어를 공유하고, 안정화된 게시글을 AI가 분석해 피드에서 활용할 수 있게 한다.
- 포함 범위: 게시글 작성·조회·수정·삭제, 사진·영상, 댓글·반응, 보관함, 게시글 AI 분석.
- 제외 범위: 게시글 분석의 재시도 횟수·대체 모델·품질 통과 기준과 텍스트 모델 버전은 확정하지 않는다.
- 핵심 규칙: 게시글 본문에 미디어를 첨부하지 않거나 사진 1~4장 또는 영상 1개를 첨부한다. 사진과 영상은 한 게시글에서 섞지 않는다. 게시글 내용이 10분간 안정된 후 Spring Boot가 FastAPI에 분석을 요청한다.
- 완료 조건: 피드 동작은 이 문서와 [API 계약](../contracts/API.md)의 API-POSTS·API-COMMENTS·API-REACTIONS·API-FILES 항목을, 분석 저장은 DATA_MODEL의 `post_analyses`를 만족한다.

## 확정된 동작

1. 활성 그룹 구성원은 텍스트 게시글을 작성·조회·수정·삭제할 수 있다.
2. 게시글 본문은 최대 140자다. 미디어는 없거나 이미지 1~4장 또는 영상 1개이며, 이미지와 영상을 함께 첨부하지 않는다.
3. 사진 1장은 단일 이미지로 표시하고 사진 2~4장은 고정 분할하지 않고 `display_order` 순서대로 가로로 넘겨 표시한다.
4. 프론트엔드는 미디어를 최적화하고 제품 DB에는 최적화본 URL만 저장한다. 업로드 원본은 보관하지 않는다.
5. 게시글에 댓글을 작성·조회·수정·삭제할 수 있다. 댓글 답글 기능은 현재 범위에 없다.
6. 게시글 반응은 정의된 반응 종류로 토글한다. 같은 반응은 해제하고 다른 반응은 갱신한다.
7. 그룹 구성원은 피드와 보관함을 조회하고, 보관함에서 구성원·날짜 필터를 사용할 수 있다.
8. 게시글 생성·수정 후 10분간 수정되지 않으면 Spring Boot가 `API-POSTS-006`으로 `post_id`를 전달해 FastAPI 분석을 시작한다.
9. FastAPI는 게시글 원문과 미디어를 DB에서 직접 읽고, 분석 결과를 게시글 분석 레코드에 상태와 요약으로 직접 저장한다. 저장 직전 게시글 `updated_at`이 요청 때와 같은지 다시 확인한다.
10. 분석 요약은 최대 500자이며 중립적·사실 중심이어야 하고, 원문에 없는 키워드나 내용을 만들지 않는다.
11. 이미지·영상 분석에는 `Gemini 3.5 Flash`를 사용한다. 텍스트 전용 게시글에는 `Gemini 2.5 Flash Lite`를 우선 고려 중이지만 최종 모델·버전은 확정하지 않는다.
12. 분석 모델·버전은 `post_analyses`에 별도 저장하지 않고, FastAPI가 완료 콜백 없이 상태와 결과를 직접 기록한다.
13. `API-POSTS-004`는 `groupIds[]`별로 독립된 게시글 행을 만들며 `batch_id`를 사용하지 않는다. 다만 여러 그룹을 실제 선택·노출하는 제품 규칙은 그룹 소속 정책 결정 전까지 구현 기준으로 확정하지 않는다.

확정된 예외:

- 조건: 분석 대상 게시글이 존재하지 않거나 비어 있다.
  - 처리: 분석을 완료하지 않고 [API 계약](../contracts/API.md)에 명시된 오류를 반환한다.
- 조건: 동일 게시글 분석이 이미 진행 중이다.
  - 처리: 중복 분석을 시작하지 않고 `ANALYSIS_IN_PROGRESS`를 따른다.
- 조건: 게시글이 분석 요청 후 다시 수정된다.
  - 처리: 현재 분석을 `FAILED`로 두고 `summary`와 `analyzed_at`을 저장하지 않는다. 다음 10분 안정화 구간 이후 Spring Boot가 다시 요청할 수 있다.
- 조건: AI 분석이 실패하거나 시간 초과한다.
  - 처리: 분석 상태를 `FAILED`로 저장하고 요약을 채우지 않는다. 재시도 횟수와 추가 오류 정책은 미결정이다.

## 구현 규칙

- 권한: 활성 그룹 구성원만 해당 그룹 피드와 게시글을 이용한다. 게시글 수정·삭제는 작성자 권한을 따른다. 댓글 수정·삭제도 작성자 권한을 따른다.
- 상태와 전이: 게시글 분석 상태는 `PENDING` → `SUCCESS` 또는 `FAILED`다. 재분석은 최신 안정화 요청으로 수행하며, 분석 중 중복 실행을 허용하지 않는다.
- API:
  - 처리 주체: 일반 게시글·미디어·댓글·반응은 Spring Boot가 처리한다. 분석 시작 요청과 `post_analyses` 결과 처리는 FastAPI가 담당하며, Spring Boot는 안정화 시점에 내부 요청을 보낸다.
  - Method와 Path: `API-POSTS-001~007`, `API-COMMENTS-001~004`, `API-REACTIONS-001`, `API-FILES-001`을 [API 계약](../contracts/API.md)에서 참조한다.
  - 핵심 입력·결과: 게시글·미디어·댓글·반응 CRUD와 분석 요청 결과는 API 계약에 정의된 입력·성공 결과·오류를 사용한다.
- 데이터:
  - 관련 엔티티: `posts`, `post_media`, `comments`, `post_reactions`, `post_analyses`.
  - 읽기·쓰기 소유자: Spring Boot가 일반 피드 API와 게시글 `updated_at`을 처리한다. FastAPI는 `post_analyses`를 직접 쓰고 분석 시 게시글을 읽는다. 일반 테이블의 물리적 쓰기 경계는 [DATA_MODEL](../contracts/DATA_MODEL.md)의 근거 수준을 따른다.
  - 주요 제약조건: 게시글 길이, 미디어 형식·개수·순서, 반응 중복, 분석 상태·요약 길이는 [DATA_MODEL](../contracts/DATA_MODEL.md)을 기준으로 적용한다.
- 화면:
  - 진입점: 피드, 게시글 작성·상세, 댓글, 보관함, 게시글 미디어 선택·가로 페이징.
  - 사용자에게 표시할 결과: 게시글·미디어·댓글·반응을 표시한다. AI 분석 요약의 사용자 직접 노출 여부와 분석 중·실패 안내 방식은 확정 전 임의로 추가하지 않는다.

## 인수 조건

### AC-001

- Given: 활성 그룹 구성원이 본문을 입력하고 미디어를 첨부하지 않거나 사진 1~4장 또는 영상 1개를 선택한다.
- When: 게시글을 작성한다.
- Then: 사진·영상이 섞이지 않은 유효한 게시글로 저장된다.

### AC-002

- Given: 게시글에 이미지가 2장 이상 연결되어 있다.
- When: 게시글을 조회한다.
- Then: 이미지는 가로 스크롤 순서로 표시된다.

### AC-003

- Given: 게시글 내용이 10분간 수정되지 않았다.
- When: Spring Boot가 내부 분석 요청을 보낸다.
- Then: FastAPI가 게시글을 읽고 `PENDING` 분석을 시작한다.

### AC-004

- Given: 분석이 성공했다.
- When: 분석 결과를 저장한다.
- Then: 최대 500자의 중립적 요약을 `SUCCESS` 상태로 저장한다.

### AC-005

- Given: 같은 게시글에 동일한 반응을 이미 남겼다.
- When: 같은 반응을 다시 선택한다.
- Then: 해당 반응이 해제된다.

## 미결정 사항

- 텍스트 게시글 분석에 `Gemini 2.5 Flash Lite`를 최종 채택할지와 사용할 정확한 버전.
- 텍스트 모델 품질 통과 기준과 대체 모델.
- 분석 실패 시 재시도 횟수·백오프·추가 오류 정책·서버 복구 처리.
- 분석 실패 상태를 사용자 화면에 표시하는 방식.
- 게시글 분석 요약의 사용자 화면 직접 노출 여부.
- 다중 그룹 게시글의 최종 작성·노출 규칙.
- 영상 길이·용량, 미디어 형식·코덱·메타데이터 처리와 최적화 품질 기준.
