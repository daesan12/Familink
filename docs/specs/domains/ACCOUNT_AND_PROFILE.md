# [ACCOUNT_AND_PROFILE] 계정·프로필

> 상태: 일부 확정
> 기준: 2026-07-31, 최신 확정 Notion·활성 API 명세와 승인된 모바일 인증 세션 계약

## AI 작업 컨텍스트

## 로그인 보안 보강 계약

- 로그인 실패 제한은 Redis에서 로그인 ID와 Spring이 해석한 요청 출처를 조합해 관리한다. 임의의 클라이언트 헤더는 신뢰하지 않는다.
- 15분 내 실패 5회부터 1초 시작 지수 backoff를 적용하며 차단은 최대 300초다. 차단 요청은 DB 조회와 BCrypt 실행 전에 `429 LOGIN_RATE_LIMITED`와 `Retry-After`를 반환한다.
- 정상 로그인은 실패 카운터와 차단 상태를 초기화한다.
- 이미 활성 Refresh Token이 있으면 기존 세션을 보존하고 `409 ACTIVE_SESSION_EXISTS`를 반환한다. 로그아웃·토큰 폐기·만료 후 새 로그인은 허용한다.

- 목적: 사용자가 계정을 만들고 로그인한 뒤 자신의 역할과 프로필을 관리할 수 있게 한다.
- 포함 범위: 로그인·회원가입, 모바일 인증 세션 저장·복원·무효화, 사용자 역할, 온보딩, 프로필·관심사, 탈퇴 및 개인정보 익명화.
- 제외 범위: 이메일 인증·이메일 로그인·소셜 로그인은 지원하지 않는다.
  세부 개인정보 동의 문구와 새 인증 오류 화면·안내 문구는 현재 확정
  범위에 포함하지 않는다.
- 핵심 규칙: 보호자(guardian)와 피보호자(care receiver)는 계정 전역 값이 아니라 각 그룹 멤버십의 역할이다. 탈퇴 시 개인정보는 익명화하되 서비스 기록은 보존한다.
- 완료 조건: 관련 구현이 이 문서와 [공통 규칙](../COMMON.md),
  [API 계약](../contracts/API.md)의 인증·사용자·관심사 항목과
  [화면 전이 계약](../UI_AND_NAVIGATION.md)을 함께 만족한다.

## 확정된 동작

1. 회원가입은 이름, 로그인 ID, 비밀번호, 비밀번호 확인, 성별, 생년월일을
   입력한다. 로그인 ID는 5~15자의 영문 대·소문자와 숫자만 허용하고,
   대소문자를 구분하며 소문자로 정규화하지 않고 입력 그대로 저장한다.
   비밀번호는 8~16자의 영문 대·소문자와 숫자만 허용하며 영문과 숫자를
   각각 최소 1자 포함한다. 비밀번호 확인은 클라이언트에서 일치 여부를
   검증하고 API에는 비밀번호만 전달한다. 이메일 주소와 이메일 인증 정보는
   입력하거나 전송하지 않는다.
2. 프로필 사진 등록은 회원가입 때 건너뛸 수 있다.
3. 로그인 성공 후 활성 그룹이 있으면 최근 이용 그룹의 피드로 이동한다. 활성
   그룹이 없으면 A-10 안내 화면을 표시하고, 사용자가 `가족과 연결하기`를
   선택하면 그룹 생성·가입과 승인 요청 대기를 함께 확인하는 B-3으로 이동한다.
4. 보호자와 피보호자 역할은 그룹 생성 또는 관리자의 가입 승인으로 그룹 멤버십에 부여한다.
5. 관심사는 피보호자 그룹 구성원에 연결되며 빈 목록을 포함해 0~10개를
   보유할 수 있다. 각 값은 앞뒤 공백 제거 후 1~10자여야 하며 중복을
   제거해 전체 교체한다.
6. 피보호자는 본인의 관심사를 저장하고, 같은 그룹의 활성 보호자는 그 관심사를 조회할 수 있다.
   피보호자 마이페이지에서 관심사 설정에 진입하면 현재 그룹과 본인의
   멤버십으로 서버 관심사를 먼저 조회하고, 성공한 결과만 편집할 수 있다.
   조회 중에는 편집 UI를 표시하지 않으며 실패하면 기존 로컬 값 대신 오류와
   다시 시도·뒤로 가기를 제공한다. 뒤로 가거나 현재 그룹이 바뀐 뒤 도착한
   이전 요청 결과는 반영하지 않는다.
7. 사용자는 자신의 프로필을 조회·수정할 수 있다. 같은 그룹의 활성
   구성원 프로필은 `memberId`, 조회자 기준 `displayName`, 만 나이 `age`,
   `gender`만 조회하며 로그인 ID·생년월일·사용자 ID는 반환하지 않는다.
8. 사용자가 탈퇴하면 `login_id`, `password_hash`, `name`, `birth_date`,
   `gender`, `profile_image_url`을 NULL로 익명화하고 `withdrawn_at`을 기록한다.
   같은 트랜잭션에서 사용자의 모든 기기 토큰을 비활성화한다. 사용자별
   Refresh Token을 폐기하고 탈퇴 전에 발급된 모든 Access Token을 사용자
   단위 블랙리스트로 차단한다. 작성 기록과 과거 그룹 관계는 보존하며 기존
   계정은 복구하지 않는다.
9. 인증이 필요한 기능은 Access Token을 사용하고 토큰 재발급에는 Refresh
   Token을 사용한다. 로그인은 활성 Refresh Token이 없을 때만 새 Token
   Pair를 발급한다. 이미 활성 Refresh Token이 있으면 기존 세션을 보존하고
   `409 ACTIVE_SESSION_EXISTS`를 반환한다.
10. 프로필 이미지는 `profile-image` 목적의 업로드 URL로 이미지 1개를
    업로드한 뒤 반환된 안정적인 `fileUrl`로 연결한다. 프로필 수정 요청에서
    이미지 필드를 생략하면 유지하고, `null`이면 삭제하며, 문자열이면
    교체한다.
11. Token Pair는 Android Keystore로 보호되는 버전 있는 단일 세션 레코드로
    저장한다. Access Token 만료 시각은 응답 유효 시간과 수신 시각으로
    계산하며 현재 그룹 ID는 인증 세션과 분리한다.
12. 앱 시작 시 유효한 Access Token은 바로 복원하고 만료된 Access Token은
    재발급 한 번으로 복원한다. 확정적인 재발급 실패는 세션을 지우고
    비로그인 상태로 전환하지만 네트워크·타임아웃·5xx는 저장 세션을 유지한
    재시도 가능한 복원 오류로 처리한다.
13. 사용자가 로그아웃을 확정하면 서버 로그아웃 성공 여부와 관계없이 로컬
    인증 정보를 삭제하고 기존 비로그인 진입 상태로 전환한다.

확정된 예외:

- 조건: 이미 사용 중인 로그인 ID로 가입을 시도한다.
  - 처리: 가입을 완료하지 않고 로그인 ID 중복을 알려야 한다. 구체적인 오류 응답은 [API 계약](../contracts/API.md)을 따른다.
- 조건: 탈퇴한 사용자의 기존 기록이 남아 있다.
  - 처리: 기록을 삭제하지 않고 익명화된 사용자 상태로 보존한다.

## 구현 규칙

- 권한: 사용자 본인의 계정·프로필·관심사만 수정한다. 그룹 안에서 다른 구성원의 프로필을 임의로 수정하지 않는다.
- 상태와 전이: 인증 전 사용자는 로그인 또는 회원가입을 거쳐 인증 상태가
  된다. 확정적인 재발급 실패 또는 안전한 세션 저장 교체 실패로
  `authInvalidated`가 발생하면 사용자·그룹 메모리를 비우고 기존 비로그인
  진입 상태로 전환한다. 탈퇴 후에는 개인정보가 익명화된 상태로 전환되며
  기존 계정을 복구하지 않는다.
- API:
  - 처리 주체: 인증·사용자 계정은 Spring Boot가 처리한다. AI 분석이나 통화 세션 책임을 이 문서에 추가하지 않는다.
  - Method와 Path: `API-AUTH-001~005`, `API-USERS-001~003`,
    `API-GROUPS-015`, `API-INTERESTS-001~002`를
    [API 계약](../contracts/API.md)에서 참조한다.
  - 핵심 입력·결과: 로그인 ID·인증 정보, 프로필 정보, 돌봄 대상자 관심사와 사용자 탈퇴 요청을 API 계약에 정의된 형식으로 주고받는다.
  - 모바일 인증 저장·복원·동시 재발급·무효화·로그아웃 후 로컬 삭제는
    [공통 규칙](../COMMON.md)의 인증 세션 계약을 따른다.
  - 프로필 이미지 URL은 설정된 S3 또는 허용 CDN 호스트이면서 object key가
    `profile-image/` 아래인 값만 허용한다. Spring Boot는 저장 전 스토리지
    메타데이터에서 이미지 MIME과 10 MiB 제한을 다시 검증한다.
- 데이터:
  - 관련 엔티티: `users`, `member_interests`, 탈퇴 시의 `device_tokens`.
  - 읽기·쓰기 소유자: Spring Boot가 계정·프로필·관심사 API와 관련 데이터의 모든 읽기·쓰기를 처리한다.
  - 주요 제약조건: 로그인 ID·필수 사용자 필드 제약, 관심사 중복 방지와 최대 10개 규칙을 [DATA_MODEL](../contracts/DATA_MODEL.md) 기준으로 적용한다.
  - 새 로그인 ID 규칙은 신규 가입과 로그인 ID 변경에 적용하며 기존 저장
    계정을 일괄 변환하거나 마이그레이션하지 않는다.
  - DB에는 만료되지 않는 프로필 이미지 `fileUrl`을 저장한다. 조회 시에는
    접근 가능한 CDN URL 또는 다운로드용 서명 URL을 반환한다. 교체·삭제된
    과거 객체 정리는 별도 수명주기로 처리하고 프로필 수정 성공을 막지 않는다.
- 화면:
  - 진입점: 로그인, 회원가입, 역할 선택, 프로필, 관심사 입력·수정, 탈퇴 흐름.
  - 사용자에게 표시할 결과: 인증 결과, 현재 역할·프로필·관심사, 탈퇴 완료 결과를 표시한다. 확정되지 않은 개인정보 동의 문구나 노출 범위를 임의로 확정하지 않는다.
  - 인증 복원·무효화에는 기존 비로그인 진입 상태만 재사용하며 새 화면이나
    안내 문구를 추가하지 않는다.
  - 모바일 화면은 React Native로 구현한다.

## 인수 조건

### AC-001

- Given: 인증되지 않은 사용자가 필수 정보를 입력하고 비밀번호와 비밀번호 확인이 일치한다.
- When: 회원가입을 요청한다.
- Then: 계정이 생성되고 로그인 가능한 인증 흐름으로 이어진다.

### AC-002

- Given: 사용자가 유효한 인증 정보를 갖고 있고 활성 Refresh Token이 없다.
- When: 로그인을 요청한다.
- Then: Access Token과 Refresh Token 기반 인증 결과를 받는다.
- Given: 사용자의 활성 Refresh Token이 이미 저장되어 있다.
- When: 같은 계정으로 다시 로그인을 요청한다.
- Then: 기존 Refresh Token은 유지되고 `409 ACTIVE_SESSION_EXISTS`를 받는다.

### AC-003

- Given: 피보호자 역할의 구성원이 마이페이지에서 관심사 설정에 진입한다.
- When: 현재 그룹의 본인 관심사를 조회한다.
- Then: 조회 성공 전에는 편집할 수 없고, 성공하면 서버 목록으로 편집하며,
  실패하면 기존 로컬 값을 표시하지 않고 다시 시도하거나 뒤로 갈 수 있다.
- Given: 피보호자 역할의 구성원이 관심사를 선택하거나 모두 삭제한다.
- When: 관심사를 저장한다.
- Then: 앞뒤 공백과 중복을 정리한 0~10개의 관심사로 전체 교체되고 서버가
  반환한 목록만 화면 상태에 반영된다. 실패하면 편집값을 유지해 다시 저장할
  수 있다.

### AC-004

- Given: 로그인한 사용자가 탈퇴를 요청한다.
- When: 탈퇴가 처리된다.
- Then: 개인정보는 익명화되고 모든 기기 토큰은 비활성화되며 기존 서비스
  기록은 보존된다. 모든 활성 멤버십은 종료되고 해당 멤버십의 일정 참여자
  연결은 삭제되며, 일정 자체와 작성자·멤버십 이력은 유지된다. Refresh
  Token은 폐기되고 탈퇴 전에 발급된 모든 Access Token은 차단된다.

### AC-005

- Given: 사용자가 `profile-image`로 허용된 이미지 1개를 업로드했다.
- When: 반환된 `fileUrl`로 프로필 이미지를 수정한다.
- Then: 서버가 허용 호스트·경로·스토리지 메타데이터를 검증해 안정적인
  URL을 저장한다. 필드를 생략하면 기존 이미지를 유지하고 `null`이면
  삭제한다.

### AC-006

- Given: 앱을 시작했을 때 저장된 세션이 유효하거나 Access Token만
  만료됐다.
- When: 인증 상태를 복원한다.
- Then: 유효한 세션은 저장 사용자 정보로 복원하고, 만료된 세션은 재발급
  한 번과 새 Token Pair 저장을 마친 뒤 복원한다.

### AC-007

- Given: 여러 보호 API가 동시에 `401 UNAUTHORIZED`를 반환한다.
- When: 자동 재발급을 처리한다.
- Then: 재발급 요청은 한 번만 발생하고 새 Token Pair 저장 후 각 원 요청은
  한 번만 재시도된다.

### AC-008

- Given: 사용자가 로그아웃을 확정했다.
- When: 서버 로그아웃이 성공하거나 실패한다.
- Then: 두 경우 모두 로컬 인증 정보를 삭제하고 기존 비로그인 진입 상태로
  전환한다.

## 미결정 사항

- 그룹 구성원 프로필 팝업의 시각·상호작용 세부 규칙.
- 소셜 로그인은 현재 지원하지 않는다. 향후 확장 시 제공 사업자와 계정
  병합 정책을 별도로 결정해야 한다.
- 첫 사용 온보딩은 서비스 소개·역할 안내를 제공하는 방향만 검토 중이며,
  단계·문구·건너뛰기 조건이 미결정이다.
- PC·모바일 웹의 서비스 소개·Android 다운로드 경로와 앱·웹 고객센터·FAQ를
