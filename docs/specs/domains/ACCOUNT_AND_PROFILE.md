# [ACCOUNT_AND_PROFILE] 계정·프로필

> 상태: 일부 확정
> 기준: 2026-07-27, API 명세서 2차 수정본

## AI 작업 컨텍스트

- 목적: 사용자가 계정을 만들고 로그인한 뒤 자신의 역할과 프로필을 관리할 수 있게 한다.
- 포함 범위: 로그인·회원가입, 사용자 역할, 온보딩, 프로필·관심사, 탈퇴 및 개인정보 익명화.
- 제외 범위: 소셜 로그인과 세부 개인정보 동의 문구는 현재 확정 범위에 포함하지 않는다.
- 핵심 규칙: 보호자(guardian)와 피보호자(care receiver)는 계정 전역 값이 아니라 각 그룹 멤버십의 역할이다. 탈퇴 시 개인정보는 익명화하되 서비스 기록은 보존한다.
- 완료 조건: 관련 구현이 이 문서와 [API 계약](../contracts/API.md)의 인증·사용자·관심사 항목을 함께 만족한다.

## 확정된 동작

1. 회원가입은 이름, 로그인 ID, 비밀번호, 비밀번호 확인, 성별, 생년월일을 입력한다. 비밀번호 확인은 클라이언트에서 일치 여부를 검증하고 API에는 비밀번호만 전달한다.
2. 프로필 사진 등록은 회원가입 때 건너뛸 수 있다.
3. 로그인 성공 후 활성 그룹이 있으면 최근 이용 그룹의 피드로 이동한다.
4. 보호자와 피보호자 역할은 그룹 생성 또는 관리자의 가입 승인으로 그룹 멤버십에 부여한다.
5. 관심사는 피보호자 그룹 구성원에 연결되며 한 구성원이 최대 10개까지 보유한다.
6. 피보호자는 본인의 관심사를 저장하고, 같은 그룹의 활성 보호자는 그 관심사를 조회할 수 있다.
7. 사용자는 자신의 프로필을 조회·수정할 수 있다.
8. 사용자가 탈퇴하면 `login_id`, `password_hash`, `name`, `birth_date`, `gender`, `profile_image_url`을 NULL로 익명화하고 `withdrawn_at`을 기록한다. 작성 기록과 과거 그룹 관계는 보존하며 기존 계정은 복구하지 않는다.
9. 인증이 필요한 기능은 Access Token을 사용한다. 토큰 재발급에는 Refresh Token을 사용한다.

확정된 예외:

- 조건: 이미 사용 중인 로그인 ID로 가입을 시도한다.
  - 처리: 가입을 완료하지 않고 로그인 ID 중복을 알려야 한다. 구체적인 오류 응답은 [API 계약](../contracts/API.md)을 따른다.
- 조건: 탈퇴한 사용자의 기존 기록이 남아 있다.
  - 처리: 기록을 삭제하지 않고 익명화된 사용자 상태로 보존한다.

## 구현 규칙

- 권한: 사용자 본인의 계정·프로필·관심사만 수정한다. 그룹 안에서 다른 구성원의 프로필을 임의로 수정하지 않는다.
- 상태와 전이: 인증 전 사용자는 로그인 또는 회원가입을 거쳐 인증 상태가 된다. 탈퇴 후에는 개인정보가 익명화된 상태로 전환되며 기존 계정을 복구하지 않는다.
- API:
  - 처리 주체: 인증·사용자 계정은 Spring Boot가 처리한다. AI 분석이나 통화 세션 책임을 이 문서에 추가하지 않는다.
  - Method와 Path: `API-AUTH-001~005`, `API-USERS-001~003`, `API-INTERESTS-002~003`을 [API 계약](../contracts/API.md)에서 참조한다.
  - 핵심 입력·결과: 로그인 ID·인증 정보, 프로필 정보, 돌봄 대상자 관심사와 사용자 탈퇴 요청을 API 계약에 정의된 형식으로 주고받는다.
- 데이터:
  - 관련 엔티티: `users`, `member_interests`.
  - 읽기·쓰기 소유자: Spring Boot가 계정·프로필·관심사 API를 처리한다. 일반 테이블의 물리적 쓰기 경계는 [DATA_MODEL](../contracts/DATA_MODEL.md)의 근거 수준을 따른다.
  - 주요 제약조건: 로그인 ID·필수 사용자 필드 제약, 관심사 중복 방지와 최대 10개 규칙을 [DATA_MODEL](../contracts/DATA_MODEL.md) 기준으로 적용한다.
- 화면:
  - 진입점: 로그인, 회원가입, 역할 선택, 프로필, 관심사 입력·수정, 탈퇴 흐름.
  - 사용자에게 표시할 결과: 인증 결과, 현재 역할·프로필·관심사, 탈퇴 완료 결과를 표시한다. 확정되지 않은 개인정보 동의 문구나 노출 범위를 임의로 확정하지 않는다.

## 인수 조건

### AC-001

- Given: 인증되지 않은 사용자가 필수 정보를 입력하고 비밀번호와 비밀번호 확인이 일치한다.
- When: 회원가입을 요청한다.
- Then: 계정이 생성되고 로그인 가능한 인증 흐름으로 이어진다.

### AC-002

- Given: 사용자가 유효한 인증 정보를 갖고 있다.
- When: 로그인을 요청한다.
- Then: Access Token과 Refresh Token 기반 인증 결과를 받는다.

### AC-003

- Given: 돌봄 대상자 역할의 구성원에게 관심사를 추가한다.
- When: 관심사를 저장한다.
- Then: 중복 없이 최대 10개 범위에서 저장된다.

### AC-004

- Given: 로그인한 사용자가 탈퇴를 요청한다.
- When: 탈퇴가 처리된다.
- Then: 개인정보는 익명화되고 기존 서비스 기록은 보존된다.

## 미결정 사항

- 같은 그룹 구성원에게 공개할 생년월일·성별·프로필 정보 범위와 프로필
  팝업의 세부 규칙.
- 그룹당 보호자 복수·돌봄 대상자 단일 정책 및 한 계정의 그룹 수 정책.
- 관심사 최소 입력 개수와 목록 고정 여부.
- 소셜 로그인은 현재 확장 범위이며, 제공 사업자와 계정 병합 정책이
  미결정이다.
- 첫 사용 온보딩은 서비스 소개·역할 안내를 제공하는 방향만 검토 중이며,
  단계·문구·건너뛰기 조건이 미결정이다.
- PC·모바일 웹의 서비스 소개·Android 다운로드 경로와 앱·웹 고객센터·FAQ를
  제공하는 요구는 검토 중이다. 정적 또는 서버 제공 방식과 세부 진입 경로는
  미결정이다.
- 개인정보 처리 동의와 AI 통화 이용 동의를 구분하고 선택적 마케팅·알림
  수신을 분리하는 요구는 검토 중이다. 정확한 문구, 필수·선택 항목,
  재동의 조건은 미결정이다.
- 탈퇴한 사용자가 새 계정으로 다시 가입할 수 있는지 여부.
