# [CALENDAR] 일정·캘린더

> 상태: 일부 확정
> 기준: 2026-07-27, API 명세서 2차 수정본

## AI 작업 컨텍스트

- 목적: 그룹 구성원이 공유 일정을 등록하고, AI 통화 중 날짜 기반으로 일정을 조회할 수 있게 한다.
- 포함 범위: 일정 CRUD, 참여자, 일정 시작 알림, AI 일정 조회 Tool Calling.
- 제외 범위: 기기 캘린더 연동과 미확정 알림 스케줄러 실행 계층은 포함하지 않는다.
- 핵심 규칙: 일정은 그룹 단위 공유 데이터다. 상대 날짜는 `Asia/Seoul` 기준 절대 날짜로 변환한다. Tool에는 `YYYY-MM-DD` 형식의 `target_date`만 전달한다.
- 완료 조건: 일정 구현은 이 문서와 [API 계약](../contracts/API.md)의 CALENDAR 항목을, AI 일정 조회는 AI_CALL의 Tool 계약을 함께 만족한다.

## 확정된 동작

1. 활성 그룹 구성원은 그룹 일정을 조회하고 새 일정을 등록할 수 있다.
2. 일정 작성자는 일정을 수정·삭제할 수 있다. 그룹 관리자는 작성자와 함께 수정·삭제 권한을 갖는다.
3. 일정에는 그룹·작성자·최종 수정자·제목·설명·날짜·선택적 시작·종료 시각이 연결된다.
4. 일정에 그룹 멤버를 참여자로 연결할 수 있다.
5. 일정은 앱 내부 캘린더에서 관리하며 기기 캘린더와 동기화하지 않는다.
6. 사용자가 알림 시점을 선택하거나 바꾸지 않는다. 시간 일정은 시작 1시간 전, 날짜 일정은 전날 09:00 `Asia/Seoul`에 일정 시작 알림을 한 번 생성한다.
7. AI 통화 중 날짜를 요청하면 상대 날짜를 서울 시간대 기준 절대 날짜로 바꾼 뒤 해당 날짜와 겹치는 그룹 일정을 조회한다.
8. AI Tool 조회 결과는 일정이 없을 때 빈 배열을 반환할 수 있다.
9. 일정에 참여자가 있으면 현재 활성 참여자에게만 알림을 보내고, 참여자가 없으면 그룹의 모든 활성 구성원을 대상으로 한다. 이미 탈퇴한 구성원에게 미래 일정 알림을 보내지 않는다.
10. 일정 시작 알림은 동일 수신자·일정·유형 조합의 중복 생성을 막는다. 별도 `event_reminders` 테이블은 사용하지 않는다.

확정된 예외:

- 조건: 작성자 또는 관리자가 아닌 사용자가 일정을 수정·삭제한다.
  - 처리: 권한을 거부한다. 구체적인 응답은 [API 계약](../contracts/API.md)을 따른다.
- 조건: 일정의 시작·종료 시각이 모두 입력된다.
  - 처리: 종료 시각은 시작 시각보다 빠를 수 없다.
- 조건: AI가 날짜를 해석할 수 없거나 모호한 날짜를 받는다.
  - 처리: 임의의 날짜로 변환하지 않고 사용자에게 확인을 요청한다.

## 구현 규칙

- 권한: 활성 그룹 구성원은 조회·생성할 수 있다. 작성자와 그룹 관리자는 수정·삭제할 수 있다. 참여자 연결은 일정 권한과 API 계약을 따른다.
- 상태와 전이: 일정은 생성·수정·삭제 수명주기를 갖는다. 삭제된 일정은 조회 결과에서 제외한다.
- API:
  - 처리 주체: 일정·참여자·알림 일반 업무 데이터는 Spring Boot가 처리한다.
  - Method와 Path: `API-CALENDAR-001~005`를 [API 계약](../contracts/API.md)에서 참조한다.
  - 핵심 입력·결과: 그룹 일정 목록·상세·생성·수정·삭제와 참여자 입력·성공 결과는 API 계약에 정의된 형식을 사용한다.
- 데이터:
  - 관련 엔티티: `calendar_events`, `event_participants`.
  - 읽기·쓰기 소유자: Spring Boot가 일정 API를 처리한다. 일반 테이블의 물리적 쓰기 경계는 [DATA_MODEL](../contracts/DATA_MODEL.md)의 근거 수준을 따른다.
  - 주요 제약조건: 그룹·작성자·최종 수정자·참여자 FK와 날짜·시각 일관성 제약은 [DATA_MODEL](../contracts/DATA_MODEL.md)을 따른다.
- 화면:
  - 진입점: 캘린더, 날짜별 일정 목록, 일정 상세, 일정 생성·수정.
  - 사용자에게 표시할 결과: 선택 날짜의 일정과 참여자, 생성·수정·삭제 결과를 표시한다. 일정별 알림 시점 선택 UI는 제공하지 않는다.

## 인수 조건

### AC-001

- Given: 활성 그룹 구성원이 유효한 일정 정보를 입력한다.
- When: 일정을 등록한다.
- Then: 현재 그룹의 공유 일정으로 조회된다.

### AC-002

- Given: 일정 작성자 또는 그룹 관리자다.
- When: 일정 수정 또는 삭제를 요청한다.
- Then: 해당 일정이 요청대로 변경되거나 삭제된다.

### AC-003

- Given: 시간 일정의 시작 1시간 전 또는 날짜 일정의 전날 09:00 `Asia/Seoul`에 도달한다.
- When: 알림 조건을 만족한다.
- Then: 현재 활성 대상자에게 중복 없이 일정 시작 알림을 한 번 생성한다.

### AC-004

- Given: AI Tool에 `target_date=YYYY-MM-DD`가 전달된다.
- When: 그룹의 날짜별 일정을 조회한다.
- Then: 해당 날짜와 겹치는 일정 목록을 반환하고, 없으면 빈 배열을 반환한다.

## 미결정 사항

- 상대 날짜 변환을 수행하는 애플리케이션 계층(FastAPI 또는 Spring Boot).
- 일정 알림 스케줄러를 실행하는 애플리케이션 계층과 장애 복구 정책.
- AI 날짜 표현의 모든 모호성 처리 문구.
