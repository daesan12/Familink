# [CALENDAR] 일정·캘린더

> 상태: 일부 확정
> 기준: 2026-07-28, 최신 Notion 기술 결정·AI Tool Calling 설계·API·ERD

## AI 작업 컨텍스트

- 목적: 그룹 구성원이 공유 일정을 등록하고, AI 통화 중 날짜 표현으로 그룹 일정을 조회할 수 있게 한다.
- 포함 범위: 일정 CRUD, 참여자, 일정 시작 알림, AI 일정 조회 Tool Calling.
- 제외 범위: 기기 기본 캘린더 연동과 미확정 알림 스케줄러 복구 정책.
- 핵심 경계: Spring Boot가 일정 API, 상대 날짜 해석, Tool 실행, 일정 조회와 알림 스케줄을 담당한다.
- 완료 조건: 일반 일정 기능은 [API 계약](../contracts/API.md), AI 일정 조회는 [AI_CALL](./AI_CALL.md)의 Tool 계약을 함께 만족한다.

## 확정된 동작

1. 활성 그룹 구성원은 그룹 일정을 조회하고 새 일정을 등록할 수 있다.
2. 일정 작성자 또는 그룹 관리자는 일정을 수정·삭제할 수 있다.
3. 일정은 그룹, 작성자, 최종 수정자, 제목, 설명, 날짜, 선택적 시작·종료 시각과 연결된다.
4. 일정에 그룹 구성원을 참여자로 연결할 수 있다.
5. 일정은 앱 안의 캘린더에서 관리하며 기기 기본 캘린더와 동기화하지 않는다.
6. 사용자는 알림 시점을 선택하거나 바꾸지 않는다. 시간 일정은 시작 1시간 전, 날짜 일정은 전날 09:00 `Asia/Seoul`에 일정 시작 알림을 한 번 생성한다.
7. AI 통화 중 사용자가 상대 날짜를 말하면 모델이 원문을
   `date_expression`으로 전달하고, 서버 Tool 로직이 `Asia/Seoul` 기준
   단일 날짜로 해석한 뒤 해당 날짜와 겹치는 그룹 일정을 조회한다.
8. 날짜를 하나로 확정할 수 없으면 일정을 조회하지 않고 모호성 상태를
   반환한다. 조회 결과에 일정이 없으면 빈 배열을 반환할 수 있다.
9. 일정에 참여자가 있으면 현재 활성 참여자에게만 알림을 보내고, 참여자가 없으면 그룹의 모든 활성 구성원을 대상으로 한다. 이미 탈퇴한 구성원에게 미래 일정 알림을 보내지 않는다.
10. 같은 수신자·일정·알림 유형 조합의 중복 생성을 방지한다. 별도 `event_reminders` 테이블은 사용하지 않는다.
11. 시간 데이터는 UTC 절대 시각으로 저장·교환하고 사용자 표시와 일정 알림 규칙에만 `Asia/Seoul`을 적용한다.

`get_calendar_events_by_date`의 필수 입력은 사용자의 원문 날짜 표현인
`date_expression`이다. 서버가 기준 현재 시각과 사용자 시간대를 적용해
단일 날짜로 해석한다.

## 예외

- 작성자나 관리자가 아닌 사용자의 수정·삭제 요청은 거부한다.
- 시작·종료 시각을 모두 입력했다면 종료 시각은 시작 시각보다 빨라야 할 수 없다.
- AI가 날짜 표현을 해석할 수 없거나 모호하면 임의 날짜로 변환하지 않고 사용자에게 확인을 요청한다.

## 구현 규칙

- 권한: 활성 그룹 구성원은 조회·생성할 수 있고, 작성자 또는 그룹 관리자는 수정·삭제할 수 있다.
- API: `API-CALENDAR-001`~`005`의 요청·응답·명시 오류는 [API 계약](../contracts/API.md)을 따른다.
- 데이터:
  - 관련 엔티티는 `calendar_events`, `event_participants`다.
  - 모든 읽기·쓰기는 Spring Boot가 소유한다.
  - FK와 날짜·시간 제약은 [DATA_MODEL](../contracts/DATA_MODEL.md)을 따른다.
- 모바일 화면은 React Native로 구현한다.

## 인수 조건

### AC-001

- Given: 활성 그룹 구성원이 유효한 일정 정보를 입력했다.
- When: 일정을 등록한다.
- Then: 현재 그룹의 공유 일정으로 조회된다.

### AC-002

- Given: 일정 작성자 또는 그룹 관리자다.
- When: 일정을 수정하거나 삭제한다.
- Then: 해당 일정이 요청대로 변경되거나 삭제된다.

### AC-003

- Given: 시간 일정은 시작 1시간 전이고 날짜 일정은 전날 09:00 `Asia/Seoul`이다.
- When: Spring Scheduler가 알림 조건을 만족한 일정을 찾는다.
- Then: 현재 활성 대상자에게 중복 없이 일정 시작 알림을 한 번 생성한다.

### AC-004

- Given: AI 통화에서 사용자가 날짜 표현으로 일정을 질문했다.
- When: 모델이 `date_expression`을 전달하고 서버 Tool이 표현을 해석한다.
- Then: 해당 날짜와 겹치는 그룹 일정 목록을 반환하고, 날짜가 모호하면
  조회하지 않으며 일정이 없으면 빈 배열을 반환한다.

## 미결정 사항

- 일정 알림 스케줄러의 장애·서버 재시작 후 복구 정책.
- 모호한 AI 날짜 표현에 사용할 구체적인 확인 문구.
