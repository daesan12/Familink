# UI_AND_NAVIGATION 공통 화면·내비게이션

> 상태: 일부 확정
> 기준: 2026-07-31, 최신 확정 IA·요구사항·기능 명세·모바일 아키텍처와 승인된 인증 상태 전이 계약

## AI 작업 컨텍스트

- 목적: 역할과 현재 그룹에 따라 사용자가 핵심 기능에 도달하는 화면 흐름을 고정한다.
- 포함 범위: 역할별 하단 탭, 그룹 진입·전환, 그룹 없음·대기 상태, 공통 빈 상태, 앱 시작 인증 복원·무효화 전이, IA 화면 ID와 도메인 스펙 연결.
- 제외 범위: 구현에 필수적이지 않은 색상·간격·픽셀 단위 디자인, 미확정 온보딩 세부 단계, 새 인증 오류 화면·안내 문구.
- 핵심 규칙: 로그인 후 활성 그룹이 있으면 마지막 이용 그룹의 피드로 진입하고, 모든 주요 탭은 선택 그룹의 데이터만 표시한다. AI 전화 화면과 통화 엔진만 Kotlin 네이티브로 구현하며 그 밖의 모바일 화면은 React Native로 구현한다. 화면이 없는 푸시 등록 토큰 확보 구성요소는 예외이며 경계는 [`COMMON`](./COMMON.md)을 따른다.
- 완료 조건: 현재 역할·그룹 상태에서 INDEX와 이 문서만으로 진입 경로와 상태 화면을 찾을 수 있다.

## 역할별 하단 탭

| 역할 | 하단 탭 |
|---|---|
| 피보호자 | 피드, 캘린더, AI 전화, 그룹 정보, 프로필 |
| 보호자 | 피드, 캘린더, 일일 리포트, 그룹 정보, 프로필 |

AI 전화는 피보호자에게, AI 리포트는 보호자에게 역할에 맞게 노출한다. 탭의 API·데이터 계약은 각 도메인 문서와 [`contracts/API.md`](./contracts/API.md)를 함께 참조한다.

## 주요 진입 경로

앱 시작 인증 상태는 다음 규칙을 먼저 적용한다.

- 저장 세션 확인과 필요한 재발급이 끝나기 전에는 인증 또는 비로그인
  상태로 단정하지 않는다.
- 유효한 세션을 복원하면 아래의 기존 로그인 후 경로를 사용한다.
- 세션이 확정적으로 무효하면 사용자·그룹 메모리를 비우고 기존 A-1
  비로그인 진입 상태로 전환한다.
- 네트워크·타임아웃·5xx로 복원하지 못하면 저장 세션을 유지한 채 재시도
  가능한 복원 오류로 전달한다. 성공이나 비로그인으로 바꾸지 않으며 새
  화면·버튼·안내 문구는 이 계약에서 정하지 않는다.

1. 비로그인 사용자는 로그인·회원가입 화면에서 인증한다.
2. 로그인 후 활성 그룹이 있으면 최근 이용 그룹의 피드로 진입한다.
3. 활성 그룹이 없으면 A-10 안내 화면을 먼저 표시하고, 사용자가
   `가족과 연결하기`를 선택하면 그룹 생성·초대 코드 가입과 본인의 가입 요청
   대기 상태를 함께 확인하는 B-3 화면으로 이동한다.
4. 그룹 가입 요청이 대기 중이면 B-3의 `승인 요청 대기` 영역에 대기 카드를
   표시한다. 대기 요청이 없으면 같은 영역에 빈 상태를 표시하며, 승인 전 그룹
   데이터는 조회하지 않는다.
5. 주요 화면 좌상단의 현재 그룹명을 누르면 별도 페이지가 아닌 그룹 전환 토글이 열린다.
6. 그룹 전환 후 피드·캘린더·그룹 정보·AI 기능의 데이터 범위는 선택 그룹으로 바뀐다.
7. 보호자는 리포트 화면을 좌우로 넘겨 현재 그룹의 피보호자별 리포트로 전환하고, 별도 구성원 필터는 사용하지 않는다. 화면 하단에는 현재 그룹의 피보호자 수만큼 위치 표시 전용 페이지 인디케이터 점을 표시한다. 이 전환은 조회 대상만 바꾸며 그룹이나 사용자 역할을 변경하지 않는다.
8. 메인 피드 `D-1`의 게시글 카드에는 수정·삭제 메뉴를 표시하지 않는다.
   게시글 상세 `D-3`에서 본인 게시글의 `···`를 선택하면 같은 화면 위에
   `D-3-bottom` 수정·삭제 바텀시트가 열린다. 상세 진입 중에도 역할별 하단
   탭을 유지한다.

## 그룹이 없는 상태

- 그룹이 없는 사용자는 A-10 안내 화면을 거쳐 B-3에서 그룹 생성 또는 가입
  요청을 진행하고 본인의 승인 대기 상태를 확인할 수 있다.
- 그룹이 없는 상태에서는 마이페이지 진입을 차단한다.
- B-3에서 뒤로 가면 인증 상태를 유지한 A-10 안내 화면으로 돌아가며, 그
  화면에서 로그아웃과 회원탈퇴를 이용할 수 있다.
- 활성 그룹이 있는 사용자가 다른 그룹에 가입 요청을 보낸 경우 대기·처리 결과는 앱 내부 알림에서 확인한다.
- 활성 그룹에서 보호자 또는 피보호자가 0명이 되더라도 그룹을 `PENDING`, `READ_ONLY` 또는 비활성 상태로 전환하지 않는다.

## 공통 상태 화면

확정된 상태는 다음과 같다.

- 피드에 게시글이 없으면 빈 피드와 작성 안내를 표시한다.
- 조회할 리포트가 없으면 리포트 빈 상태를 표시한다.
- 가입 요청이 처리되지 않았으면 대기 카드와 처리 대기 상태를 표시한다.
- 관리자는 가입 요청 승인·거절 결과를 알림 화면에서 확인한다.
- 공용 캘린더에 해당 날짜의 일정이 없으면 일정이 없는 날짜 상태를 표시한다.
- 앱 시작 인증 복원 중에는 인증·비로그인·빈 상태로 단정하지 않는다.
- 일시적인 인증 복원 오류는 저장 세션을 유지한 재시도 가능한 상태로
  전달한다. 구체적인 화면 표현과 문구는 확정하지 않는다.

Notion에 구체 표현이 없는 공통 상태에는 다음 보수적 구현 원칙만 적용한다.

- 로딩 중에는 성공·빈 상태로 단정하지 않고 현재 그룹과 사용자 입력을 유지한다.
- 빈 상태는 정상 조회가 완료되어 결과가 없을 때만 표시한다.
- 오류 상태를 빈 상태로 바꾸지 않으며, API가 명시한 오류 이외의 문구·재시도
  정책은 임의로 확정하지 않는다.

인증 복원 실패의 상태 분류는 [공통 규칙](./COMMON.md)을 따른다. 일반적인
네트워크 오류 문구, 재시도 버튼과 로딩 애니메이션의 구체 규칙은 확정되지
않았다. API가 명시한 오류만 [`contracts/API.md`](./contracts/API.md)에
기록한다.

### 피보호자 관심사 설정

- J-1에서 관심사 설정에 진입하면 현재 그룹의 피보호자 본인 관심사를
  조회한다. 조회가 끝나기 전에는 J-3p·J-4 편집 UI를 표시하지 않는다.
- 조회 실패는 빈 관심사로 처리하지 않고 오류 안내와 `다시 시도`, `뒤로 가기`를
  제공한다. `다시 시도`는 같은 현재 그룹·구성원으로 다시 조회한다.
- 사용자가 뒤로 가거나 현재 그룹이 바뀌면 진행 중인 조회 결과를 무효화하고
  관심사 하위 화면을 닫는다.
- 저장 실패 시 편집값을 유지해 다시 저장할 수 있게 한다. 저장 성공 시 서버가
  반환한 관심사를 반영하고 J-4p 완료 안내를 거쳐 J-1로 돌아간다.
- 저장 전 `뒤로 가기`와 `건너뛰기`는 변경 내용을 저장하지 않고 J-1로 돌아간다.

## 중요 행동 확인 및 실행 취소

`REQ-031`은 현재 검토 중인 요구사항이다. 삭제처럼 복구가 어렵거나 영향이 큰
행동 전에 사용자가 이해할 수 있는 확인·취소 절차를 제공하고, 가능한 행동에는
실행 취소를 지원하는 방향을 유지한다.

적용할 중요 행동의 목록과 실행 취소 가능 시간은 확정되지 않았다. 결정 전에는
모든 삭제·변경 행동에 동일한 확인 창이나 임의의 실행 취소 시간을 일괄
적용하지 않으며, 이 검토 방향을 확정된 인수 조건으로 사용하지 않는다.

## IA와 도메인 스펙의 관계

IA 원본의 화면 ID는 화면 진입과 사용자 행동의 근거다. 구현자는 모든 IA 목록을 매번 읽지 않고 이 문서와 [`INDEX.md`](./INDEX.md)의 관련 도메인을 먼저 읽는다. 전체 IA 70건의 매핑은 [`COVERAGE.md`](./COVERAGE.md)에서 검증한다.

| IA 영역 | 대표 화면 ID | 연결 스펙 |
|---|---|---|
| 인증·가입·그룹 없음 | `A-1`~`A-6`, `B-1`~`B-5`, `C-1` | `ACCOUNT_AND_PROFILE`, `GROUPS_AND_MEMBERSHIP` |
| 피드·게시글·알림 | `D-0`~`D-12` | `FEED_AND_MEDIA`, `NOTIFICATIONS` |
| 캘린더 | `E-1`~`E-3` | `CALENDAR` |
| AI 전화 | `F-1`~`F-3` | `AI_CALL` |
| 리포트 | `G-1`~`G-3` | `REPORTS` |
| 그룹 관리 | `H-1`~`H-9` | `GROUPS_AND_MEMBERSHIP` |
| 보호자 프로필·활동 | `I-1`~`I-7` | `ACCOUNT_AND_PROFILE`, `CARNATIONS_AND_RANKING` |
| 피보호자 프로필·관심사 | `J-1`~`J-7` | `ACCOUNT_AND_PROFILE` |
| 공통 체크리스트 | `00` | `COMMON`, 관련 도메인 |

## 미결정 사항

- `REQ-031`을 적용할 중요 행동 목록과 행동별 실행 취소 가능 시간
- 일반 공통 로딩·오류 상태의 구체 문구와 재시도 동작
- 온보딩 단계 수와 건너뛰기 범위
- IA 일부 화면 설명의 역할 명칭 불일치가 최종 화면에 미치는 영향
- 최소 지원 Android 버전과 시험 기기 목록
