# COMMON 공통 규칙

> 상태: 일부 확정
> 기준: 2026-07-31, 최신 확정 Notion·활성 API 명세·ERD와 승인된 모바일 인증 세션 계약

이 문서는 둘 이상의 도메인이 공유하는 규칙만 모은다. 도메인별 동작은 [`INDEX.md`](./INDEX.md)에서 관련 스펙을 찾는다.

## 역할과 권한

- 각 그룹 멤버십의 사용자 역할은 `보호자(guardian)`와 `피보호자(care receiver)`다. 계정 전역 역할로 해석하지 않는다.
- 그룹 관리자는 역할과 별개인 관리자 권한으로 승인·구성원 관리·그룹 관리를 수행한다.
- 승인된 그룹원만 해당 그룹의 그룹 데이터에 접근한다.
- AI 전화는 피보호자만 사용하고, AI 리포트는 보호자만 조회한다.
- AI는 가족을 대체하는 서비스가 아니라 가족 소통을 돕는 보조 수단이다.
- 관리자가 구성원의 역할을 바꾸면 변경된 권한을 즉시 적용한다. 역할 구성원이 부족해도 그룹을 `PENDING`, `READ_ONLY` 또는 비활성으로 바꾸지 않는다.
- 그룹별 세부 권한과 각 API의 권한은 [`contracts/API.md`](./contracts/API.md)를 기준으로 한다.

## 인증과 요청 경계

- 로그인·재발급·로그아웃은 API 계약의 인증 흐름을 따른다.
- 클라이언트는 Access Token을 사용한다. Refresh Token 재발급은 `API-AUTH-004`, 로그아웃은 `API-AUTH-005` 계약을 따른다.
- Access Token은 서버에 상시 저장하지 않는 자체 검증 JWT이며 유효 기간은
  설정값으로 관리하고 기본값은 30분이다. 로그아웃한 Access Token만
  `blacklist:{accessToken}` 키에 `logout` 값과 남은 만료 시간 TTL로
  저장하며 인증 필터는 서명·만료 검증 후 블랙리스트를 확인한다.
- Refresh Token은 JWT로 발급해 사용자별 단일 Redis 키
  `refresh:{userId}`의 값으로 저장한다. 유효 기간은 설정값으로 관리하고
  기본값은 14일이며 Redis 키에도 같은 TTL을 적용한다.
- 새 로그인은 같은 사용자의 기존 Refresh Token을 덮어써 단일 세션을
  유지한다. 재발급은 현재 저장된 Refresh Token만 원자적으로 새 토큰으로
  회전하고 TTL을 기본 14일로 다시 설정하며, 기존 토큰의 재사용을 거부한다.
- 로그아웃은 인증에 사용한 Access Token을 블랙리스트에 등록하고, 요청한
  Refresh Token이 현재 저장값이면 해당 사용자 키를 삭제한다.
- 현재 회원가입과 로그인은 로그인 ID와 비밀번호를 사용한다. 이메일
  회원가입·이메일 로그인·이메일 인증은 지원하지 않는다.
- AI 전화 전용 Kotlin 모듈은 Spring Boot에 Access Token, 선택한
  `persona_id`, `sdp_offer`를 전달한다.
- `persona_id`는 1~6의 고정 번호이며 페르소나 DB 테이블이나 외래 키를
  사용하지 않는다.
- Spring Boot는 토큰, 현재 그룹 소속, 피보호자 권한을 검증한다.
- AI Tool과 프롬프트에는 현재 그룹과 현재 세션의 권한 범위를 벗어난 데이터를 포함하지 않는다.

### 모바일 클라이언트 인증 세션

- Token Pair는 Android Keystore로 보호되는 암호화 저장소에 한 사용자당
  하나의 버전 있는 레코드로 저장한다. AsyncStorage, 일반
  SharedPreferences, 소스 코드와 로그에는 평문 토큰을 저장하지 않는다.
  네트워크 요청용 메모리 캐시는 허용하지만 영속 저장소를 원본으로 본다.
- 세션 레코드의 최소 항목은 `tokenType`, `accessToken`,
  `accessTokenExpiresAt`, `refreshToken`, `user{id,name}`이다.
  `accessTokenExpiresAt`은 응답의 `accessTokenExpiresIn`과 수신 시각으로
  계산한다. 현재 그룹 ID는 인증 세션과 분리해 그룹 문맥에서 관리한다.
  Token Pair 회전 시 레코드 전체를 안전하게 교체한다.
- 앱 시작 시 세션 레코드가 없거나 형식·버전 검증에 실패하면 로컬 값을
  정리하고 비로그인 상태로 시작한다. Access Token이 유효하면 저장된 최소
  사용자 정보로 복원하고, 만료됐으면 `API-AUTH-004`를 한 번 호출해 새
  Token Pair 저장을 마친 뒤 복원한다.
- 앱 시작 재발급의 `400 INVALID_REQUEST` 또는
  `401 INVALID_REFRESH_TOKEN`은 확정적인 인증 실패이므로 세션을 지우고
  비로그인 상태로 전환한다. 네트워크·타임아웃·5xx는 저장 세션을 유지하고
  인증 완료나 비로그인으로 단정하지 않은 재시도 가능한 복원 오류로
  전달한다.
- 보호 API 요청에는 `Authorization: Bearer <accessToken>`을 붙인다.
  보호 API의 `401 UNAUTHORIZED`에만 자동 재발급하고 `403`에는 재발급하지
  않는다. 동시에 발생한 여러 `401`은 하나의 진행 중인 재발급 Promise를
  공유한다. 새 Token Pair 저장을 마친 뒤 대기한 원 요청을 각각 한 번만
  재시도한다. 재시도 요청, 재발급 요청 자체와 Access Token이 필요 없는
  인증 요청에는 다시 재발급을 적용하지 않는다.
- 확정적인 재발급 실패 또는 안전한 세션 레코드 교체 실패는 인증 정보를 한
  번만 지우고 공통 `authInvalidated` 신호를 발생시킨다. 앱 루트는 이
  신호로 사용자·그룹 관련 메모리 상태를 비우고 기존 비로그인 진입 상태로
  전환한다. 오류 분기는 응답 `message`가 아니라 HTTP 상태와 `code`를
  사용한다.
- 사용자가 로그아웃을 확정하면 서버 로그아웃 결과와 무관하게 현재 기기의
  로컬 인증 정보를 삭제하고 비로그인 상태로 전환한다. 서버 호출 실패는
  호출자에게 반환하되 실패한 Refresh Token을 다시 저장하지 않는다. FCM
  token 비활성화 실패의 재시도 정책은 이 규칙에서 정하지 않는다.

## 서비스와 데이터 소유권

- 현재 제품 클라이언트 범위는 Android 모바일 앱이며 iOS 앱은 제외한다.
  최소 지원 Android 버전과 시험 기기 목록은 미결정이다.
- 모바일 앱의 AI 전화 화면과 통화 엔진만 Android Kotlin 네이티브
  모듈로 구현한다. AI 전화를 제외한 모바일 화면과 기능은 React Native로
  구현하며, React Native와 Kotlin의 브리지는 AI 전화 경계에서만 사용한다.
- 모든 서비스 API, 인증·인가, AI 오케스트레이션과 DB 접근은 Spring Boot
  단일 백엔드가 담당한다.
- AI 전화 음성은 Kotlin 모듈과 OpenAI Realtime이 WebRTC로 직접
  주고받는다. Spring Boot는 SDP 교환, Sideband WebSocket, Tool Calling,
  발화 완료 전사와 통화 상태를 처리한다.
- Spring Boot는 마지막 수정 후 10분이 지난 게시글을 직접 조회해 Gemini로
  분석하고 `post_analyses`에 저장한다.
- 게시글 분석의 Gemini 호출은 SSAFY GMS 프록시를 사용한다.
  `GMS_API_KEY`는 프록시 인증 키로 서버에서만 보관하며
  `x-goog-api-key` 헤더로 전달한다.
- Spring Boot는 통화 세션·전사·건별 리포트·일일 리포트를 생성·갱신하고,
  게시글 분석과 리포트 생성 시 별도 백엔드를 두지 않고 각 도메인의
  Gemini Gateway를 호출한다.
- PostgreSQL이 공용 데이터 저장소다. 상세 테이블·관계·쓰기 소유권은 [`contracts/DATA_MODEL.md`](./contracts/DATA_MODEL.md)를 기준으로 한다.

## 시간과 날짜

- 상대 날짜를 절대 날짜로 해석할 때 기준 시간대는 `Asia/Seoul`이다.
- 모델은 원문 날짜 표현을 `date_expression`으로 Tool에 전달하고, 서버가
  `Asia/Seoul` 기준 현재 시각과 사용자 시간대를 적용해 단일 날짜로
  해석한다. 날짜가 모호하거나 해석되지 않으면 임의 조회하지 않는다.
- 일일 리포트는 Spring Scheduler가 `Asia/Seoul` 기준 매일 22시에
  생성한다. `report_date=D`의 집계 구간은 `[D-1 22:00, D 22:00)`이며
  시작 시각은 포함하고 종료 시각은 제외한다. 정확히 `D 22:00:00`에
  종료된 통화는 `D+1` 리포트에 포함한다. 종료 시각 조건은 UTC
  `Instant`로 변환해 조회한다.
- DB 저장·서버 로그·API timestamp는 UTC로 관리하고 PostgreSQL 시각
  컬럼은 `TIMESTAMPTZ`를 사용한다. 사용자 화면에서는 서비스 시간대로
  변환해 표시한다.

## 개인정보·녹음·대화 텍스트

- AI 통화 녹음 원본은 저장하지 않는다.
- 통화 중 AI 발화 자막만 항상 표시한다. 사용자 발화 자막과 자막 끄기 기능은 제공하지 않는다. 완료된 사용자·AI 발화 단위 텍스트는 내부 통화 처리와 리포트 생성에 사용한다.
- 보호자에게 전체 통화 전문이나 원본 음성을 제공하지 않는다. 보호자 화면에는 건별 요약과 보호자 전달 메시지만 노출한다.
- 건별 감정은 저장·일일 리포트 집계에 사용하지만 건별 리포트 화면에는 표시하지 않는다.
- 회원 탈퇴 시 개인정보는 익명화하고 서비스 기록은 보존한다. 정확한 보존 기간·삭제 일정은 확정하지 않는다.
- 개인정보 처리·AI 통화 동의의 구체 문구와 재동의 정책은 미결정이다.

## 여러 기능에서 공유되는 제한

- 현재 그룹을 기준으로 피드, 일정, AI Tool, 리포트의 데이터 범위를 제한한다.
- 그룹 전환은 별도 그룹 선택 페이지가 아니라 현재 화면의 그룹 토글에서 수행한다.
- 피드의 미디어는 원본이 아닌 프론트엔드 최적화본을 저장·제공한다. 지원 포맷·코덱·메타데이터 정책은 미결정이다.

## 미결정 사항

- 통화 텍스트 보존 기간과 삭제 정책
- 개인정보·AI 통화 동의 문구, 동의 유형, 재동의 시점
- 미디어 지원 포맷·코덱·메타데이터 제거 목록
