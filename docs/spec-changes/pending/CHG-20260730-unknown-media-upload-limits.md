# 사진·영상 업로드 제한 및 검증

- 상태: 제안
- 제안자: 장대산
- 작성일: 2026-07-30
- 차단 변경: 아니오
- 영향 스펙·계약: `docs/specs/domains/FEED_AND_MEDIA.md`, `docs/specs/contracts/API.md`
- 관련 작업: S3 실제 업로드·게시글 미디어 E2E 검증

## 기존 내용

사진·영상의 파일 용량, 영상 길이, 미디어 형식과 코덱 검증은 미결정 상태다.

## 제안 내용

- 사진은 파일 1개당 최대 10MB로 제한한다.
- 영상은 파일 1개당 최대 100MB, 최대 60초로 제한한다.
- 허용 MIME 타입은 이미지 `image/jpeg`, `image/png`, `image/webp`, 영상 `video/mp4`로 한다.
- 프론트 선택 단계와 백엔드 presigned URL 발급 단계에서 1차 검증한다.
- 게시글 생성·수정 시 백엔드가 S3 `HeadObject`로 실제 크기와 `Content-Type`을 재검증한다.
- 영상은 백엔드 실행 환경의 FFprobe로 실제 재생 시간을 검증한다.
- 제한값은 환경변수로 조정 가능하게 한다.

## 변경 근거

현재 presigned PUT은 요청자가 전달한 메타데이터와 실제 S3 객체가 다를 수 있다. 업로드 URL 발급 전 요청값을 확인하고 게시글 저장 직전에 S3 객체를 재확인해야 우회 업로드를 막을 수 있다. S3 버킷 정책만으로 영상 재생 시간을 검증할 수 없으므로 FFprobe를 사용한다.

## 확인 영향

- 영향 API: `POST /files/presigned-urls`, 게시글 생성·수정 API
- 영향 계약: 미디어 업로드 요청의 허용 MIME·용량과 게시글 저장 전 검증 규칙
- 영향 화면: 미디어 선택 시 제한 초과 파일 안내
- 검증 범위: 백엔드 단위·통합 테스트, 프론트 타입 검사·단위 테스트, 실제 S3 이미지·영상 E2E

## 확인이 필요한 질문

- 위 제한값과 허용 형식을 공식 스펙으로 확정할 것인가?
- 영상 컨테이너·코덱 제한을 `video/mp4` MIME 검사만으로 충분하다고 볼 것인가?
