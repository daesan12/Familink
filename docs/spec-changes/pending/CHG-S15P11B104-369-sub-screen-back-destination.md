## 기존 내용

- `docs/specs/UI_AND_NAVIGATION.md`는 "역할별 하단 탭"과 "주요 진입 경로"에서
  화면에 **도달하는** 경로만 규정한다. 알림, 게시글 보관함, 가입 승인 대기처럼
  어느 하단 탭도 소유하지 않는 화면에서 뒤로 갔을 때의 목적지 규정은 없다.
- 같은 문서 "주요 진입 경로" 8번은 게시글 상세 `D-3` 항목 안에서 "상세 진입
  중에도 역할별 하단 탭을 유지한다"만 정한다. 뒤로 가기 목적지는 다루지 않는다.
- `docs/specs/domains/NOTIFICATIONS.md`에는 알림을 탭했을 때의 이동 목적지
  규정이 없다. "확정된 동작" 1~2는 목록 조회와 읽음 처리까지다.
- `CHG-S15P11B104-270`(pending) "제안 내용" 1번은 "하단 탭 루트에서 시스템 뒤로
  가기를 누르면 피드 탭으로 돌아간다. 피드 탭 루트에서만 앱을 종료한다"까지
  정한다. 하위 화면은 탭 루트가 아니므로 이 규칙이 목적지를 정해 주지 않는다.
- `CHG-S15P11B104-270`의 "변경 근거"와 "확인된 영향"은 알림·보관함을 하단 탭
  라우트의 일부로 적고 있었다. "하단 탭 8개 라우트(`feed`, `calendar`, `report`,
  `aiCall`, `groupInfo`, `profile`, `notifications`, `archive`)"가 그 문구였다.
  작성 시점(2026-08-04)에는 셸이 단일 `activeRoute` 상태로 이 둘을 탭과 같은
  층에서 다뤘기 때문이며, S15P11B104-367 이후로는 사실이 아니다.
  **본 변경에서 함께 정정했다.**
- `CHG-20260805-rudgh8182-notification-tap-deep-link`(pending) "제안 내용" 1번
  표는 `GROUP_JOIN_REQUEST` 알림의 목적지를 "그룹정보의 가입 승인 화면"으로
  적고 있었고, 같은 문서 "확인된 영향"의 영향 화면도 "그룹정보(가입 승인)"였다.
  S15P11B104-336에서 딥링크 목적지가 달라졌으므로 **본 변경에서 함께 정정했다.**
- 두 정정은 사실 서술을 현재 구조에 맞춘 것이며, 두 제안의 승인 여부와 승인 범위는
  그대로 미결이다.

## 제안 내용

`docs/specs/UI_AND_NAVIGATION.md`에 하위 화면 뒤로 가기 규칙을 추가한다.

1. 하위 화면(알림, 게시글 보관함, 가입 승인 대기)은 현재 화면 위에 쌓이고, 뒤로
   가기는 그 화면을 **열었던 진입 지점**으로 돌아간다. 피드 목록에서 알림을 열면
   피드 목록으로, 알림에서 가입 승인 대기를 열면 알림으로, 그룹정보 메뉴에서 가입
   승인 대기를 열면 그룹정보 홈으로 돌아간다. 목적지는 화면이 어느 탭에 속하는지가
   아니라 **어디서 열었는지**로 정한다. 가입 승인 대기는 알림에서 여는 인스턴스와
   그룹정보 탭이 소유한 인스턴스가 각각 존재하며, 두 경우 모두 이 규칙 하나로
   목적지가 정해진다.
2. 하위 화면 위에서 다시 화면을 열면 그 화면도 위에 쌓이고, 뒤로 가기는 직전
   하위 화면으로 돌아간다. 알림에서 게시글 상세를 열면 뒤로 가기가 알림으로,
   보관함에서 열면 보관함으로 돌아간다.
3. `CHG-S15P11B104-270` 1번(탭 루트 → 피드 탭, 피드 탭 루트에서만 종료)은
   **탭 루트에만** 적용한다. 하위 화면과 그 위에 쌓인 화면에는 적용하지 않는다.
4. 화면 내 뒤로 가기 버튼과 시스템 뒤로 가기의 목적지를 일치시킨다
   (`CHG-S15P11B104-270` 4번을 하위 화면에도 적용한다).
5. 앱 밖 푸시로 하위 화면이나 상세에 바로 진입한 경우에는 진입 지점이 없으므로
   피드 목록을 아래에 깔고, 뒤로 가기는 피드 목록으로 간다. 앱이 뒤로 가기로
   바로 종료되지 않게 하는 Android 인공 백스택 관례를 따른다.

`CHG-20260805-rudgh8182-notification-tap-deep-link` 1번 표의
`GROUP_JOIN_REQUEST` 목적지 서술은 위 1번에 맞춰 본 변경에서 정정했다. 그 제안의
승인 범위는 달라지지 않는다 — 목적지 화면은 같고, 도달 방식과 뒤로 가기 목적지만
현재 구조로 맞췄다.

## 변경 근거

- QA에서 하위 화면 뒤로 가기가 진입 지점이 아닌 화면으로 나가는 결함 3건이
  보고되었다.

  | 경로 | 수정 전 | 수정 후 |
  |---|---|---|
  | 알림 → 게시글 상세 → 뒤로 | 피드 목록 | 알림 |
  | 알림 → 가입 요청 알림 → 가입 승인 대기 → 뒤로 | 그룹정보 홈 | 알림 |
  | 게시글 보관함 → 게시글 상세 → 뒤로 | 피드 목록 | 보관함 |

- 원인은 모든 화면 이동을 `StackActions.popTo('MainTabs', { …, initial: false })`
  하나로 정규화한 것이다. 이 dispatch가 진입 지점 오버레이를 pop하고 방문하지
  않은 부모 화면을 합성해, 뒤로 갈 대상 자체를 없앴다.
- 두 번째 결함에는 원인이 하나 더 있었다. 승인 대기가 그룹정보 탭 스택 화면이라
  딥링크의 탭 전환이 피드 탭 스택을 언마운트했고, `useNavigationBuilder`의
  cleanup이 그 중첩 state를 지워 알림 화면이 소멸했다.
- 구현은 네 티켓으로 끝났다. 366(회귀 테스트·하위 화면 포커스 신호 도입),
  367(셸 스택 층 제거, 알림·보관함을 피드 탭 스택 화면으로), 368(게시글 상세를
  진입 지점 위에 쌓기), 336(가입 승인 대기의 알림 진입 경로를 공유 하위 화면으로).
  336은 화면을 이동시킨 것이 아니라 **알림에서 도달하는 인스턴스를 추가**했다.
  그룹정보 탭 스택의 등록분은 그대로 남아 그룹정보 메뉴 진입 경로를 담당한다
  (`frontend/src/features/group-info/screens/GroupInfoScreen.tsx`의
  `GroupInfoStack.Screen name="JoinApproval"`).
- 구현 위치는 `frontend/src/app-shell/AppShell.tsx`(하위 화면 진입·포커스 신호),
  `frontend/src/features/feed/screens/FeedScreen.tsx`(하위 화면 라우트 등록),
  `frontend/src/app-shell/types.ts`(`SharedSubRoute` 집합)이다.
- 회귀 테스트는 `frontend/src/app-shell/AppShell.subScreens.test.tsx`,
  `frontend/src/app-shell/AppShell.test.tsx`,
  `frontend/src/features/feed/screens/FeedScreen.test.tsx`,
  `frontend/src/app-shell/navigation.test.mjs`에 있다. 각 티켓에서 프로덕션
  분기를 되돌리면 해당 테스트가 실패하는 것을 확인했다.
- 3번의 한정이 필요한 이유는 두 규칙이 같은 화면에 동시에 적용되면 결과가
  달라지기 때문이다. 알림 위 게시글 상세에 `CHG-270` 1번을 적용하면 피드 탭으로
  가고, 이 제안 2번을 적용하면 알림으로 간다. 후자가 QA 기대 동작이다.
- 5번은 콜드 스타트에 진입 지점이 존재하지 않는다는 사실에서 나온다. 푸시로 앱을
  열면 스택에 알림 화면이 없으므로 1번을 만족시킬 대상이 없다.

## 확인된 영향

- 영향 도메인: 특정 도메인 규칙이 아니라 공통 화면 전환 규칙이다.
  `NOTIFICATIONS`, `FEED_AND_MEDIA`, `GROUPS_AND_MEMBERSHIP`의 화면 흐름 서술과
  맞물린다.
- 영향 계약: `UI_AND_NAVIGATION` 화면 전이 계약. API·데이터 계약 변경은 없다.
- 영향 화면: 알림, 게시글 보관함, 가입 승인 대기, 게시글 상세.
- 검증 범위: frontend Jest(`npx jest --runInBand`), TypeScript 타입 검사, ESLint,
  구조 검사. 실제 푸시 3상태(포그라운드·백그라운드·앱 종료) 뒤로 가기는
  에뮬레이터 수동 확인으로 각 티켓에서 완료했다.
- 커버리지 갱신 후보: `docs/specs/COVERAGE.md`의
  `REQ-009 역할별 화면 및 하단 내비게이션` 행. `CHG-S15P11B104-270`과 같은 행이므로
  두 제안을 함께 반영해야 한다. 확인 필요.

## 확인이 필요한 질문

- **하위 화면의 하단 탭바 표시 규칙이 아직 규정되지 않았다.** 현재 구현은
  알림·보관함에서는 탭바를 유지하고 가입 승인 대기에서만 숨긴다. 후자는 탭 루트가
  아니라 결정 화면이므로 그룹정보 탭에서 열 때와 같은 모습을 유지한다는 팀
  결정이다. 반면 확인된 사용자 의도는 "하단 탭을 눌렀을 때 처음 뜨는 화면에만
  탭바가 보인다"이며, 이는 `UI_AND_NAVIGATION.md` "주요 진입 경로" 8번의 "상세
  진입 중에도 역할별 하단 탭을 유지한다"와 충돌한다. 뒤로 가기 목적지와 독립된
  결정이므로 이 제안에서 확정하지 않고 별도 작업으로 남긴다.
- **일정·리포트 알림에서 진입한 화면은 위 1·2번을 아직 만족하지 못한다.** 알림
  에서 일정 알림이나 리포트 알림을 누르고 뒤로 가면 알림으로 돌아오지 않는다.
  근거는 목적지가 화면이 아니라는 점이다. 일정 상세(`E-2p`)는 캘린더 화면 위
  모달이고 통화 리포트 상세도 리포트 화면 내부 모달이므로 내비게이션 스택에
  쌓이지 않아, 뒤로 가기가 pop할 대상이 없다. 규칙을 적용하려면 두 상세를 스택
  화면으로 승격하는 작업이 선행되어야 한다. 승격 범위와 시점 결정이 필요하다.
- 3번의 한정은 읽기 편하도록 `CHG-S15P11B104-270` 1번 본문에도 함께 적었다. 두
  제안 중 하나만 승인하면 그 한정의 근거가 불완전해지므로 **함께 승인해야 한다.**
  분리 승인이 필요하면 어느 쪽에 한정을 남길지 확인 필요.
