# AI 통화 발화 길이와 턴 구성 규정 추가

- 상태: 일부 승인
- 제안자: 손수호
- 작성일: 2026-08-05
- 차단 변경: 아니오
- 영향 스펙·계약: [`AI_CALL`](../../specs/domains/AI_CALL.md)
- 관련 작업: S15P11B104-300

## 기존 내용

[`docs/specs/domains/AI_CALL.md`](../../specs/domains/AI_CALL.md)에는 AI가 한 턴에
얼마나 말하는지에 대한 규정이 없다. 페르소나 관련 `구현 규칙`(151~155줄)은 말투,
성별 기반 호칭, 사투리 빈도, 정체성 경계와 프롬프트 섹션 구성만 정한다.

- 151~152줄: `모든 페르소나는 관계형 말투만 사용하며 실제 가족·지인·고용인이라고
  주장하지 않는다. 정체를 물으면 해당 말투로 AI 말동무임을 밝힌다.`
- 153~155줄: `페르소나 프롬프트는 Persona, Identity Boundary, Address,
  Speech Style, Dialect, Variety, Sample Phrases로 구분하고, 예시 발화는 그대로
  반복하지 않고 말투 참고용으로만 사용한다.`

발화 길이와 관련된 기존 문구는 `AI 발화 실시간 자막`(31~32줄)뿐이며, 이는 자막
표시와 전사 처리 범위이지 발화 분량 규정이 아니다.

## 제안 내용

`AI_CALL` 도메인 스펙의 `구현 규칙`에 다음 목표 동작을 추가한다.

- AI의 대화 답변은 두 문장 이내로 하고, 한 문장은 25자 안쪽으로 유지한다.
  소리 내어 읽을 때 약 10초를 기준으로 한다.
- 도구 결과 안내, 실패 안내와 프롬프트가 정한 고정 문구는 위 상한의 예외로 두고,
  필요한 내용까지만 말한다.
- 한 턴은 사용자의 말에 대한 반응 한 마디로 끝내고, 더 물을 것이 있을 때만 질문
  하나를 덧붙인다. 한 턴에 질문을 두 개 이상 넣지 않는다.
- 한 턴에는 한 가지 주제만 다루고, 당일 게시글 소식과 일상 이야기를 한 턴에 함께
  넣지 않는다. 당일 게시글은 한 턴에 한 건만 다룬다.
- 페르소나 `Sample Phrases`는 호칭 치환 후에도 위 문장 길이 상한을 지킨다.

## 변경 근거

- AI 전화 사용자 피드백에서 한 턴 발화가 음성 대화 기준으로 길다는 지적이 나왔다.
  상한 수치(두 문장·25자)는 사용자가 세 가지 후보 중 명시적으로 선택했다.
- 구현 시점의 프롬프트는 길이 상한을 `직접적인 답변` 항목에만 적용해, 이 앱의 주
  사용 패턴인 일상 잡담과 가족 게시글 이야기 턴에는 상한이 없었다.
  [`AiCallPromptComposer.java`](../../../backend/src/main/java/com/ssafy/s15p11b104/domain/call/service/AiCallPromptComposer.java)
  `# Verbosity` 섹션에서 확인했다.
- 초기 설계 문서 [`AI_CALL_PLAN.md`](../../../AI_CALL_PLAN.md) 183줄은
  `기본 답변은 짧은 1~2문장으로 제한한다`로 모든 답변을 대상으로 했으나, 로컬
  스펙에는 이 항목이 반영되지 않았고 구현은 일부 답변만 제한했다.
- 현재 이 규정의 유일한 기록 위치는
  [`AiCallPromptComposerTest`](../../../backend/src/test/java/com/ssafy/s15p11b104/domain/call/service/AiCallPromptComposerTest.java)의
  `limitsSpokenResponseLength` 문자열 단정이다. 스펙 근거가 없어 이후 프롬프트를
  수정할 때 판단 기준 없이 되돌아갈 수 있다.
- 리뷰에서 페르소나 비서 예시 발화 3건이 호칭 치환 후 26~32자로 새 상한을
  초과해, 상한 지시와 예시가 서로 모순된다는 점이 확인되었다.

## 확인된 영향

- 영향 도메인: `AI_CALL`. 정체 공개 조건은 이 제안의 대상이 아니다. 정체 공개는
  기존 스펙 152줄 기준으로 되돌리는 구현 수정이므로 스펙 변경이 필요하지 않다.
- 영향 계약: 없음. API 요청·응답, 데이터 모델, 인증·권한은 변경되지 않는다.
- 영향 화면: 없음. AI 발화 자막 표시 방식은 그대로이며 발화 내용의 분량만 달라진다.
- 검증 범위: 시스템 프롬프트에 상한 문구가 유지되는지 확인하는 단위 테스트와,
  페르소나 예시 발화가 호칭 치환 후 상한을 지키는지 확인하는 단위 테스트. 실제
  발화 분량은 단위 테스트로 검증할 수 없어 에뮬레이터 통화 QA로 확인한다.
- 확인 필요: 상한 수치가 정서 교류 목적을 해치지 않는지는 통화 QA 결과로만 판단할
  수 있다. QA에서 대화가 딱딱하다는 반응이 나오면 수치 재조정이 필요하다.

## 결정 및 반영

- 결정: 일부 승인. 사용자가 후보 중 명시적으로 선택한 답변 최대 두 문장·
  문장당 25자 안쪽의 수치 범위만 반영한다. 약 10초 기준, 도구·실패·고정 문구
  예외, 턴당 질문 수, 한 턴 한 주제, 게시글 한 건 제한과 `Sample Phrases`
  적용 범위는 구체적인 승인 근거가 없어 미결정으로 남긴다.
