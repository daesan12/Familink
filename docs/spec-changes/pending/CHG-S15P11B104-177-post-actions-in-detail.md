# 게시글 수정·삭제 진입점을 상세 화면으로 제한

- 상태: 제안
- 제안자: 강다영
- 작성일: 2026-07-30
- 차단 변경: 아니오
- 영향 스펙·계약: `FEED_AND_MEDIA`, `UI_AND_NAVIGATION`
- 관련 작업: `S15P11B104-177`

## 기존 내용

- `docs/specs/domains/FEED_AND_MEDIA.md`의 확정된 동작 1은 활성 그룹 구성원이 게시글을 작성·조회·수정·삭제할 수 있다고 정의하지만, 수정·삭제 메뉴의 화면별 진입 위치는 정하지 않는다.
- `docs/specs/UI_AND_NAVIGATION.md`의 IA 매핑은 피드·게시글 화면을 `D-0`~`D-12`로 연결하지만, `D-1` 피드와 `D-3` 상세 화면 중 어디에서 본인 글 메뉴를 제공할지는 명시하지 않는다.

## 제안 내용

- 메인 피드 `D-1`의 게시글 카드에는 본인 글 여부와 관계없이 수정·삭제 `···` 메뉴를 표시하지 않는다.
- 게시글 상세 `D-3`에서는 본인이 작성한 게시글에만 `···` 메뉴를 표시한다.
- 상세 화면의 `···`를 선택하면 같은 상세 화면 위에 `D-3-bottom` 수정·삭제 바텀시트를 표시한다.
- 수정·삭제 확인과 후속 콜백 계약은 유지하며, 메뉴 위치 변경으로 API·권한 규칙은 변경하지 않는다.
- 상세 진입 중에도 앱의 기존 역할별 하단 탭은 유지한다.

## 변경 근거

- 2026-07-30 사용자 결정: 피드를 탐색하는 중 즉시 수정·삭제하는 흐름보다 게시글 내용을 확인한 상세 화면에서 해당 작업을 실행하는 흐름이 더 자연스럽다고 판단했다.
