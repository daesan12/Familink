# 회원가입 완료 단계의 뒤로 가기 동작 규정

- 상태: 제안
- 제안자: 손수호
- 작성일: 2026-08-03
- 차단 변경: 아니오
- 영향 스펙·계약: `docs/specs/domains/ACCOUNT_AND_PROFILE.md`, `docs/specs/UI_AND_NAVIGATION.md`
- 관련 작업: S15P11B104-272

## 기존 내용

- `docs/specs/domains/ACCOUNT_AND_PROFILE.md` "확정된 동작" 1~2번은 회원가입의
  입력 항목과 프로필 사진 건너뛰기만 규정하고, 여러 입력 단계 사이의 이동이나
  가입 성공 후 완료 안내 단계의 뒤로 가기 동작은 규정하지 않는다.
- `docs/specs/UI_AND_NAVIGATION.md` "화면 전이 계약"은 "비로그인 사용자는
  로그인·회원가입 화면에서 인증한다"만 정하고, B-3과 관심사 하위 화면(J-3p·J-4)의
  뒤로 가기 결과는 명시하는 반면 회원가입 단계 흐름의 뒤로 가기 결과는 명시하지
  않는다.

## 제안 내용

`docs/specs/UI_AND_NAVIGATION.md`의 화면 전이 계약에 다음 규칙을 추가한다.

- 회원가입 입력 단계에서 뒤로 가면 직전 입력 단계로 돌아가고, 첫 입력 단계에서
  뒤로 가면 회원가입 흐름을 종료해 시작 화면으로 돌아간다.
- 회원가입 요청이 성공해 완료 안내 단계에 도달하면 이전 입력 단계로 돌아갈 수
  없다. 완료 안내 단계에는 화면 내 뒤로 가기 조작을 제공하지 않으며, 시스템
  뒤로 가기는 소비해 화면을 유지하고 앱을 종료하지 않는다.
- 완료 안내 단계에서 다음 단계로 이동하는 조작은 `완료` 하나로 유지한다.

## 변경 근거

- QA에서 완료 안내 단계(5/5) 좌측 상단 뒤로 가기 버튼으로 성별 선택 단계로
  복귀할 수 있는 결함이 확인되었다.
- 계정이 이미 생성된 뒤 입력 단계로 복귀하면 같은 로그인 ID로 재가입을 시도해
  `LOGIN_ID_DUPLICATED`가 발생하고 1단계까지 되돌려지는 것이 코드에서 확인된다.
  `frontend/src/features/auth/screens/SignupFlowScreen.tsx`의 `handleBack`과
  `applySignupFailure` 경로다.
- 완료 단계 진입 시 시스템 뒤로 가기 동작은 스펙에 근거가 없어 사용자가
  "무시하고 화면 유지"로 결정했다.
- 구현과 회귀 테스트는
  `frontend/src/features/auth/screens/SignupFlowScreen.test.tsx`의
  "완료 단계는 뒤로가기 버튼을 숨기고 시스템 Back으로도 입력 단계로 돌아가지
  않는다"에서 검증했다.
