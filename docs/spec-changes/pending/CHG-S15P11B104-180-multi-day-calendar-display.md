# 월간 캘린더의 여러 날 일정 표시 방식

- 상태: 일부 승인
- 제안자: 사용자
- 작성일: 2026-07-31
- 차단 변경: 예
- 영향 스펙·계약: `CALENDAR`, `UI_AND_NAVIGATION`의
  `E-1`·`E-2`·`E-2p`·`E-3`, `API-CALENDAR-001`,
  `API-GROUPS-005`
- 관련 작업: `S15P11B104-180`, `S15P11B104-181`

## 기존 내용

`docs/specs/domains/CALENDAR.md`는 일정의 `eventDate`와 `endDate`가
시작 날짜와 종료 날짜이며, 조회 날짜와 하루라도 겹치는 일정을 반환한다고
확정한다. 그러나 같은 문서의 `미결정 사항`에는 월간 캘린더에서 여러 날
일정을 표시하는 방식을 막대 또는 날짜별 개별 표시 중 결정하지 않았다고
기록되어 있다.

`docs/specs/UI_AND_NAVIGATION.md`는 캘린더 화면을 `E-1`~`E-3`으로
매핑하고 일정이 없는 날짜의 빈 상태를 요구하지만, 월간 셀 안의 일정 표시
방식은 정하지 않는다.

`docs/specs/contracts/API.md`의 `API-CALENDAR-001` 일정 목록은
`id`, `title`, `eventDate`, `endDate`, `startAt`, `endAt`만 반환한다.
목록에서 삭제 권한을 판단할 작성자 또는 `canDelete` 정보가 없다.
`API-GROUPS-005` 구성원 목록은 `memberId`, `userId`, `displayName`,
`role`, `isManager`만 반환해 프로필 이미지 URL을 제공하지 않는다.

## 제안 내용

- 월간 캘린더 `E-1`은 일정의 `eventDate`부터 `endDate`까지 날짜 칸
  아래에 이어지는 가로 막대로 기간을 표시한다.
- 기간이 주 경계를 넘으면 해당 주의 마지막 날짜에서 막대를 끊고 다음 주의
  첫 날짜부터 이어서 표시한다.
- 하루짜리 일정은 해당 날짜 아래의 짧은 막대로 표시한다.
- 같은 날짜에 여러 일정이 겹치면 서로 다른 막대를 세로로 쌓아 표시한다.
- 날짜를 누르면 `E-2`에서 그 날짜와 겹치는 일정 목록을 표시하고, 목록
  항목을 누르면 `E-2p` 상세 팝업을 연다.
- `E-1` 상단은 현재 그룹 전환 버튼을 좌측에, 일정 추가 버튼을 우측에
  표시한다.
- 월 제목 옆의 이전·다음 달 버튼과 별도 `오늘` 버튼은 표시하지 않는다.
  월 이동은 달력을 위·아래로 미는 제스처만 사용한다.
- 일정이 하나 이상 겹치는 날짜의 날짜 숫자에만 원형 표시를 사용한다.
  오늘이라는 이유만으로 원형 표시를 사용하지 않으며, 선택 날짜에도 네모나
  별도의 원형 테두리를 추가하지 않는다.
- 달력 날짜 위에는 요일 행을 표시한다. 표시할 정확한 요일 범위는 확인이
  필요하다.
- 달력을 위로 밀면 다음 달, 아래로 밀면 이전 달로 이동한다.
- 일정 추가 버튼을 누르면 현재 선택한 날짜를 초기 날짜로 사용하는 `E-3`
  일정 생성 화면으로 이동한다.
- 여섯 주 달력은 하단 고정 내비게이션 위에 오류·빈 상태를 표시할 공간을
  남기도록 날짜 행 높이와 여백을 조정한다. 오류와 재시도 버튼은 하단
  내비게이션 또는 시스템 제스처 영역 뒤에 배치하지 않는다.
- 현재 그룹을 변경하면 같은 캘린더 화면에서 새 그룹의 일정으로 다시
  조회한다.
- `E-2`는 화면 아래에서 올라오는 바텀시트로 표시하고, 일정 행을 누르면
  `E-2p` 상세 팝업을 연다. 목록 행에는 별도 삭제 버튼을 표시하지 않는다.
- `E-2p`는 선택한 일정의 세부 내용·작성자·참여자와 `수정`, `삭제` 버튼을
  표시한다. 작성자와 참여자는 프로필 사진을 표시하고, 사진이 없으면 기본
  프로필 이미지를 사용한다.
- `E-2p`의 수정 버튼은 선택한 일정의 기존 값을 채운 `E-3` 편집 화면으로
  이동한다. 삭제 버튼을 누르면 삭제 확인창을 먼저 표시한다. 취소하면 아무
  상태도 변경하지 않고, 확인한 경우에만 삭제 요청을 보낸다. 삭제 성공 시
  상세 팝업을 닫고 월간 막대와 선택 날짜 목록에서 즉시 제거하며, 실패 시
  상세 팝업과 기존 일정을 유지한 채 재시도 가능한 오류를 표시한다.
- `E-3`의 하루종일은 생성 시 기본으로 켜고, 작성자는 현재 사용자를
  자동 표시한다. 참여자 추가 버튼은 현재 그룹의 가족 구성원 선택을 연다.
- 구현 기준은 와이어프레임의 목업 데이터를 고정 표시하는 데 그치지 않는다.
  실제 일정 상태를 기준으로 월 이동·날짜 선택·다일 일정 배치·그룹 전환·
  생성·상세·수정·삭제 결과가 서로 일관되게 갱신되는 일반적인 캘린더 앱
  동작을 제공한다.
- 구현은 두 Jira 작업으로 나눈다. `S15P11B104-180`은 실제 일정 조회,
  월간 캘린더, 날짜 선택, 선택 날짜 바텀시트, 일정 상세와 상세에서의 삭제
  확인·삭제 요청·조회 상태 갱신을 담당한다. `S15P11B104-181`은 일정
  생성·수정, 참여자 선택과 시간 설정을 담당한다. 두 작업은 동일한 일정
  모델과 API 계층을 사용해 최종적으로 하나의 연속된 캘린더 기능으로
  연결한다.
- 기간 막대 자체는 `API-CALENDAR-001`·`002`의 기존
  `eventDate`·`endDate`로 구현한다. 다만 목록의 삭제 권한 표시와
  작성자·참여자 프로필 이미지는 현재 계약만으로 구현할 수 없어 공용 API
  응답 보완 방식의 결정이 필요하다.

## 변경 근거

- 사용자가 `S15P11B104-180` 구현 계획을 위해 제공한 `E-1`, `E-2`,
  `E-2p`, `E-3` Figma 프레임과 추가 요구사항은 날짜 칸 아래에 이어지는
  막대, 월 전환, 선택 날짜 목록, 상세 팝업, 생성·수정 화면 흐름을 사용한다.
- 2026-07-31 반영된 `docs/specs/contracts/API.md`의
  `API-CALENDAR-001`·`002`는 `endDate`를 반환하므로 기간 막대의 시작과
  끝을 계산할 수 있다.
- `API-CALENDAR-001`에는 삭제 권한 판정 필드가 없고,
  `API-GROUPS-005`에는 `profileImageUrl`이 없어 제공된 Figma와 사용자
  요구사항을 실제 서버 데이터로 구성할 수 없다.
- 2026-07-31 사용자는 구현 화면 검증 후 일정 추가 버튼·그룹 전환 버튼의
  위치, 월 이동 버튼 제거, 오늘 버튼 제거, 일정 날짜의 원형 표시,
  날짜 행 밀도와 하단 오류 영역을 구체적으로 수정 요청했다.
- 2026-07-31 사용자는 상세 화면 검증 중 수정 버튼 누락을 지적하고, 삭제도
  목록 행이 아니라 일정 상세 화면에서 수행하도록 요청했다.

## 확인된 영향

- 영향 도메인: 일정·캘린더
- 영향 계약: 기간 막대는 기존 계약을 사용한다. 삭제 버튼 권한과 프로필
  이미지는 `API-CALENDAR-001` 및 `API-GROUPS-005` 또는 동등한 조회
  계약의 보완이 필요하다.
- 영향 화면: 월간 캘린더 `E-1`, 선택 날짜 일정 목록 `E-2`, 상세 팝업
  `E-2p`, 일정 생성·편집 `E-3`, 공통 앱 셸 캘린더 헤더
- 검증 범위: 하루 일정, 같은 주의 기간 일정, 주 경계를 넘는 기간 일정,
  겹치는 일정, 일정 날짜 원형 표시, 월 스와이프 전환, 그룹 전환,
  우측 일정 추가 버튼, 선택 날짜 목록, 하단 내비게이션과 오류 상태의
  비겹침, 상세 팝업, 프로필 대체 이미지, 상세 수정·삭제 버튼, 삭제 확인,
  삭제 성공·실패 상태, 생성·편집 초기값 전달

## 확인이 필요한 질문

- 한 날짜에 표시 가능한 막대 수를 넘으면 초과 일정을 어떻게 알릴 것인가.
- 같은 날짜에 여러 일정이 겹칠 때 막대와 목록을 어떤 순서로 정렬할 것인가.
- Figma는 `일`~`토` 일곱 요일을 표시하지만 사용자 설명은
  `월`~`금`을 명시한다. 주말을 포함한 일곱 요일을 표시하는가.
- “아이폰 내부 캘린더와 같은 시간 설정”에서 필요한 동작은 날짜·시간
  휠 선택, 하루종일 전환 시 시간 숨김, 시작 변경 시 종료 자동 이동 중
  어디까지인가.
- 삭제 버튼을 작성자·그룹 관리자에게만 노출하기 위해
  `API-CALENDAR-001`에 `creatorMemberId` 또는 `canDelete`를 추가할 것인가.
- 작성자·참여자 사진을 위해 `API-GROUPS-005` 구성원 항목에
  `profileImageUrl`을 추가할 것인가, 일정 상세가 표시용 구성원 정보를
  직접 반환하게 할 것인가.

## 결정 및 반영

- 결정: 일부 승인. `S15P11B104-180`과 `S15P11B104-181`로 구현 범위를 나누되,
  실제 서버 데이터와 공통 상태·API 계층을 사용해 하나의 완성된 캘린더
  기능으로 연결한다. 수정과 삭제 진입점은 일정 상세 팝업에 배치하고,
  삭제는 확인창에서 사용자가 확인한 경우에만 수행한다. 삭제 요청과 화면
  상태 갱신은 `S15P11B104-180`, 편집 화면은 `S15P11B104-181`에서 연결한다.
  월간 다일 막대·월 이동·표시 밀도·프로필 이미지와 나머지 확인 질문은
  승인 범위가 명확하지 않아 공식 스펙에 반영하지 않는다.
