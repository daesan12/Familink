# 시연용 일일 리포트 수동 생성 경로 추가

- 상태: 승인
- 제안자: 이종철
- 작성일: 2026-08-06
- 차단 변경: 예
- 영향 스펙·계약: `REPORTS`, `API-REPORTS-002`, 신규 일일 리포트 생성 요청 API, 리포트 화면
- 관련 작업: `S15P11B104-113`

## 기존 내용

- `docs/specs/domains/REPORTS.md`의 `AI 작업 컨텍스트`, `확정된 동작`, `구현 규칙`은 일일 리포트를 `Asia/Seoul` 기준 매일 22시에 생성하고 사용자용 리포트 재생성 API와 관리 화면은 제공하지 않는다고 정한다.
- 같은 문서는 기준 구간에 종료된 통화의 건별 리포트가 모두 준비된 뒤 일일 리포트를 생성하고, 같은 피보호자·기준일의 결과를 재생성하지 않는다고 정한다.
- `docs/specs/contracts/API.md`의 `API-REPORTS-002`는 일일 리포트와 해당 날짜의 통화 목록 조회만 제공하며 수동 생성 상태나 생성 요청 계약은 제공하지 않는다.

## 제안 내용

1. 스토어 배포 전 시연 기간에 한해 현재 운영 빌드의 리포트 화면에 일일 리포트 수동 생성 버튼을 제공한다.
2. 버튼은 `Asia/Seoul` 기준 오늘 날짜와 현재 보고 있는 피보호자 한 명만 대상으로 한다.
3. 서버가 반환하는 생성 상태는 다음 네 값으로 구분한다.
   - `NOT_READY`: 저장된 건별 리포트가 없어 수동 생성할 수 없다.
   - `AVAILABLE`: 오늘 일일 리포트와 활성 생성 작업이 없고 저장된 건별 리포트가 하나 이상 있다.
   - `GENERATING`: 수동 또는 정기 생성 작업이 접수되어 유효한 single-flight claim을 보유한다.
   - `READY`: 오늘 일일 리포트가 이미 저장되어 있다.
4. 버튼은 `AVAILABLE`에서만 활성화하고 `NOT_READY`·`GENERATING`에서는 비활성화하며 `READY`에서는 표시하지 않는다. 오늘이 아닌 날짜에서는 표시하지 않는다.
5. 수동 생성은 오늘 기준 구간에 이미 저장된 건별 리포트가 하나 이상이면, 같은 구간에 아직 건별 리포트가 준비되지 않은 통화가 있더라도 준비된 건별 리포트만 입력으로 사용한다.
6. 기존 22시 정기 생성은 현재의 전체 준비 조건과 집계 구간을 유지한다. 수동 생성으로 같은 피보호자·기준일 결과가 이미 저장됐으면 기존 멱등 처리로 건너뛴다.
7. 수동 생성 요청은 기존과 같은 그룹의 활성 보호자 권한을 적용하고, 영속 claim과 `(care_receiver_member_id, report_date)` Unique로 중복 AI 호출과 중복 저장을 방지한다.
8. 시연 종료 후 버튼, 생성 요청 API, 생성 상태 계약과 수동 생성 경로를 함께 제거하고 데모 DB를 초기화한다.

## 변경 근거

- 사용자 결정: 일일 리포트의 운영 규칙인 22시 생성을 유지하면서 시연 발표에서는 원하는 시점에 생성 결과를 보여줄 수 있어야 한다.
- 사용자 결정: 별도 데모 빌드·서버를 만들지 않고 현재 빌드와 모든 데모 계정을 사용하며, 발표 후 DB 초기화와 임시 기능 제거를 수행한다.
- 사용자 결정: 현재 피보호자·오늘 날짜만 대상으로 하고, 저장된 건별 리포트가 하나 이상이면 누락된 건별 리포트가 있어도 준비된 입력만으로 생성한다.
- 현재 코드: `DailyReportScheduler`는 22시에 `DailyReportGenerationDispatcher`를 호출하고, `DailyReportGenerationService`는 기존 리포트·claim·입력 버전을 검사해 중복 저장을 막는다.
- 현재 화면: `ReportScreen`은 이전 최신 일별 리포트를 유지할 수 있으므로, 선택한 오늘 날짜의 생성 상태를 별도로 보존해야 버튼 조건을 정확히 판단할 수 있다.
