# 무그룹 사용자의 A-10 안내 화면 경유

- 상태: 반영
- 제안자: 사용자
- 작성일: 2026-07-29
- 차단 변경: 예
- 영향 스펙·계약: `UI_AND_NAVIGATION`, `ACCOUNT_AND_PROFILE`
- 관련 작업: `S15P11B104-168`, 후속 그룹 생성·가입·승인 대기 화면 작업

## 기존 내용

`docs/specs/UI_AND_NAVIGATION.md`와
`docs/specs/domains/ACCOUNT_AND_PROFILE.md`는 로그인 성공 후 활성 그룹이 없으면
그룹 생성 또는 초대 코드 가입을 선택하는 무그룹 화면으로 곧바로 이동한다고
정의한다.

## 제안 내용

- 인증에 성공한 사용자에게 활성 그룹이 하나라도 있으면 A-10과 B-3을 건너뛰고
  최근 이용 그룹의 피드로 이동한다.
- 활성 그룹이 없으면 가입 요청 유무와 관계없이 A-10 안내 화면을 먼저 표시한다.
- A-10은 환영 인사와 그룹 연결 필요성을 설명하고, 명시적인
  `가족과 연결하기` 버튼으로 B-3에 이동한다.
- B-3에서는 `새 그룹 만들기`와 `코드로 참여하기` 중 하나를 선택할 수 있으며,
  같은 화면에서 본인의 가입 승인 대기 상태를 확인한다.
- 대기 중인 가입 요청이 없으면 B-3의 `승인 요청 대기` 영역에 빈 상태를
  표시하고, 요청이 있으면 해당 영역에 대기 카드를 표시한다.
- B-3의 뒤로 가기는 A-10으로 돌아간다.
- A-10의 로그아웃은 확인 후 비인증 A-1 화면으로 돌아간다.
- A-10의 회원 탈퇴는 후속 회원 탈퇴 화면으로 연결할 수 있는 탐색 인터페이스만
  준비하고, `S15P11B104-168`에서는 탈퇴 화면과 API를 구현하지 않는다.
- 그룹이 생성되거나 가입이 승인된 뒤에는 A-10과 B-3을 기본 진입 경로로
  사용하지 않는다. 이후의 새 그룹 생성과 코드 참여는 별도 그룹 관리 진입점에서
  제공한다.

## 변경 근거

2026-07-29 사용자가 제공한 Figma 흐름에서 로그인 바텀시트 이후 A-10을 거쳐
B-3로 이동하도록 요청했다. A-10을 자동으로 넘기는 화면으로 두기보다, 무그룹
상태를 설명하고 사용자가 다음 행동을 선택해 시작하도록 해야 화면의 목적과
접근성이 명확해진다. B-3는 그룹 생성·가입 행동과 가입 승인 대기 상태를 한
화면에서 제공하므로, 가입 요청 이후에도 사용자가 현재 상태와 가능한 다음
행동을 함께 파악할 수 있다.

- 로그인 바텀시트: Figma 노드 `22:3232`
- A-10 안내 화면: Figma 노드 `22:3224`
- B-3 그룹 연결·승인 대기: Figma 노드 `84:243`

## 확인된 영향

- 영향 도메인: 인증 후 진입, 그룹 생성·가입 온보딩
- 영향 계약: API·데이터 계약 변경 없음
- 영향 화면: A-1 로그인 바텀시트, A-10 안내, B-3 그룹 연결·승인 대기,
  그룹 피드
- 검증 범위: 그룹 유무 및 가입 요청 상태별 초기 경로, A-10에서 B-3 이동,
  B-3의 승인 요청 빈 상태·대기 카드, B-3 뒤로 가기, 로그아웃 확인 후 A-1 복귀,
  기존 그룹 보유 사용자 회귀
