# Java 코드 컨벤션

> 기준: NAVER 캠퍼스 핵데이 Java 코딩 컨벤션, 2026-07-28 확인
> 적용 범위: 프로젝트의 모든 `*.java` 파일

이 문서는 프로젝트가 채택한 Java 규칙이다. 원문 전체를 구현 중 다시 조회하지
않아도 되도록 필수 규칙을 로컬에 정리한다. 공통 운영 방식은
[`README.md`](./README.md)를 따른다.

## 기준 자료

- [NAVER 캠퍼스 핵데이 Java 코딩 컨벤션](https://naver.github.io/hackday-conventions-java/)
- [NAVER Checkstyle·Formatter 설정](https://github.com/naver/hackday-conventions-java/tree/master/rule-config)

## 파일과 선언

### 필수

- UTF-8, LF, 파일 마지막 새줄을 사용한다.
- 한 소스 파일에는 하나의 최상위 클래스 또는 인터페이스만 선언한다.
- `package`와 각 `import` 선언은 줄을 나누지 않는다.
- 와일드카드 import는 static import에서만 허용한다.
- 한 줄에는 한 문장만 작성하고 하나의 선언문에는 변수 하나만 선언한다.
- 배열 대괄호는 변수명이 아니라 타입 뒤에 붙인다.
- `long` 리터럴에는 소문자 `l` 대신 대문자 `L`을 붙인다.
- 애너테이션은 대상 선언의 바로 윗줄에 둔다. 같은 선언에 여러 애너테이션이
  있으면 각각 한 줄에 작성한다.

## 이름

### 필수

- 패키지 이름은 소문자로 작성하고 대문자나 언더스코어로 단어를 구분하지 않는다.
- 클래스와 인터페이스는 `UpperCamelCase`를 사용한다.
- 클래스는 명사 또는 명사절, 인터페이스는 명사·명사절 또는 형용사·형용사절로
  이름을 짓는다.
- 메서드, 변수와 매개변수는 `lowerCamelCase`를 사용한다.
- 메서드 이름은 동사로 시작한다. 변환 메서드와 빌더 메서드는 `to`, `with`
  같은 전치사로 시작할 수 있다.
- 상태를 가지지 않는 `static final` 상수는 `UPPER_SNAKE_CASE`를 사용한다.
- 테스트 클래스 이름은 대상 이름 뒤에 `Test`를 붙인다.
- 식별자에는 영문, 숫자와 언더스코어만 사용한다. 한국어 발음을 영문으로
  옮긴 이름은 사용하지 않는다.
- 널리 합의되지 않은 축약어와 임시 변수를 제외한 한 글자 이름은 사용하지 않는다.

## 들여쓰기와 중괄호

### 필수

- NAVER 원문 기준에 따라 들여쓰기는 하드 탭을 사용한다.
- 탭 하나는 화면에서 공백 네 칸 너비로 표시한다.
- 클래스, 메서드와 제어문 블록마다 들여쓰기 한 단계를 추가한다.
- 여는 중괄호는 선언이나 제어문의 마지막에 두는 K&R 스타일을 사용한다.
- `else`, `catch`, `finally`와 `do-while`의 `while`은 닫는 중괄호와 같은
  줄에 둔다.
- 조건문과 반복문 본문이 한 줄이어도 중괄호를 생략하지 않는다.
- 빈 블록은 의도가 명확한 경우 `void close() {}`처럼 같은 줄에서 닫을 수 있다.

```java
public class ReportService {
	public Report createReport(CallSession session) {
		if (session.isCompleted()) {
			return generateReport(session);
		}

		throw new IllegalStateException("통화가 완료되지 않았습니다.");
	}
}
```

## 줄바꿈과 공백

### 필수

- 한 줄은 최대 120자를 사용한다. `package`와 `import`는 예외로 한 줄을
  유지한다.
- 줄을 나누면 원래 들여쓰기보다 한 단계 이상 추가한다.
- 이항·삼항 연산자는 다음 줄이 아니라 앞줄 끝에 둔다.
- 쉼표 뒤, 제어문 키워드와 여는 소괄호 사이, 여는 중괄호 앞에 공백을 둔다.
- 메서드 이름과 여는 소괄호 사이에는 공백을 두지 않는다.
- 줄 끝 공백을 남기지 않는다.

## 주석

- 공개 API의 계약과 사용법은 Javadoc으로 작성한다.
- Javadoc 첫 문장은 대상의 책임을 요약한다.
- 구현 코드가 이미 말해 주는 내용을 주석으로 반복하지 않는다.
- 경고 억제와 검사 제외 주석을 편의를 위해 추가하지 않는다. 필요한 경우 이유와
  최소 범위를 함께 기록한다.

## 프로젝트 적용

- Spring Boot의 패키지, 클래스와 메서드 이름도 위 규칙을 그대로 따른다.
- 프레임워크가 생성한 코드와 외부에서 복사한 스키마 생성물은 직접 수정하지 않는다.
- Java Checkstyle이 구성되면 해당 모듈의 `checkstyle` 검사를 완료 조건으로
  사용한다.
- Checkstyle이 구성되지 않은 상태에서는 이 문서의 파일, 이름, 들여쓰기,
  중괄호와 120자 제한을 수동으로 확인하고 `NOT CONFIGURED`로 보고한다.
