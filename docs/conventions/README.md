# 코드 컨벤션 운영 기준

이 폴더는 프로젝트 소스 코드의 공식 컨벤션을 관리한다. 외부 컨벤션의 이름이나
AI의 사전 지식만으로 규칙을 추론하지 않고, 대상 언어의 로컬 문서를 구현과
리뷰의 기준으로 사용한다.

## 적용 문서

| 대상 파일 | 컨벤션 |
|---|---|
| `*.java` | [`java.md`](./java.md) |
| `*.kt`, `*.kts` | [`kotlin.md`](./kotlin.md) |
| `*.ts`, `*.tsx` | [`react-native.md`](./react-native.md) |

설정 파일, 생성 코드, 외부 소스처럼 일반 규칙을 적용하기 어려운 파일은 해당
언어 문서에 명시된 예외만 허용한다. 문서에 없는 예외를 임의로 만들거나 검사
규칙을 비활성화하지 않는다.

## 규칙 우선순위

1. 현재 작업과 가장 가까운 `AGENTS.md`의 명시적 규칙
2. 이 폴더의 언어별 컨벤션
3. 저장소에 포함된 포맷터·린터·컴파일러 설정
4. 언어 또는 프레임워크의 공식 컨벤션

언어별 문서와 자동 검사 설정이 충돌하면 한쪽을 임의로 우회하지 않는다. 작업을
중단하고 충돌한 규칙과 파일을 보고한 뒤 프로젝트 기준을 먼저 일치시킨다.

## 규칙 표현

- **필수**: 새 코드와 변경한 코드가 반드시 지켜야 한다.
- **권장**: 특별한 이유가 없으면 따른다.
- **금지**: 새로 도입하지 않는다.
- 기존 코드가 컨벤션과 다르더라도 요청 범위 밖의 파일까지 일괄 정리하지 않는다.
- 변경한 줄 주변의 작은 정리는 허용하지만 별도 리팩터링이 필요하면 범위를
  분리한다.

## 작업 순서

1. 수정할 파일의 언어별 컨벤션을 먼저 읽는다.
2. 기존 모듈의 구조와 용어를 확인한다.
3. 기능 변경과 필요한 테스트를 함께 작성한다.
4. 모듈에 구성된 포맷·린트·타입 검사·테스트를 실행한다.
5. 자동 검사 도구가 없으면 설치하거나 설정을 바꾸지 않고 `NOT CONFIGURED`로
   보고한 뒤 문서 기준으로 수동 점검한다.
6. 검사 예외나 경고 억제가 필요하면 근거와 최소 범위를 명시한다.

## 공통 파일 규칙

- 소스 파일 인코딩은 UTF-8을 사용한다.
- 줄 끝은 LF를 사용하고 파일 마지막에 새줄 하나를 둔다.
- Windows 명령 스크립트인 `*.bat`, `*.cmd`만 줄 끝에 CRLF를 사용한다.
- 줄 끝 공백과 사용하지 않는 import를 남기지 않는다.
- 비밀값, 토큰, 비밀번호와 개인 환경 경로를 소스에 하드코딩하지 않는다.
- 이름은 역할과 도메인 의미를 드러내며 불필요한 축약어와 한 글자 이름을
  피한다. 반복문의 짧은 인덱스처럼 범위가 명확한 경우만 예외로 한다.
- 주석은 코드 동작을 반복하지 않고 제약, 이유, 외부 계약처럼 코드만으로
  드러나지 않는 내용을 설명한다.

## 변경 관리

- 기준 원문이나 프로젝트 선택이 달라지면 언어별 문서의 `기준`과 관련 규칙을
  함께 갱신한다.
- 포맷터·린터를 도입하거나 버전을 변경할 때는 이 문서의 검증 절차와 언어별
  문서를 함께 확인한다.
- 자동 생성 파일은 생성 원본 또는 생성 설정과 함께 변경한다. 생성 결과만
  손으로 고치지 않는다.
