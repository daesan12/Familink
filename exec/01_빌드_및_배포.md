`JAVA_HOME`을 Backend 빌드에서는 JDK 21, Android 빌드에서는 JDK 17로 전환한다.
운영 Backend 이미지는 Dockerfile 안에서 JDK 21로 빌드되므로 운영 호스트에 Gradle을
별도로 설치할 필요는 없다.

위 IDE 버전은 포팅 매뉴얼 작성 PC에서 확인한 값이다. Android Studio 자체는 내장
JBR 25.0.2로 실행되지만, 프로젝트의 Android Gradle 빌드는 JDK 17을 기준으로 한다.
Docker 버전은 저장소가 요구하는 최소 호환 기준이며, 설치된 운영 서버의 정확한 버전은
배포 전에 다음 명령으로 기록한다.

```bash
docker version
docker compose version
```

## 3. Backend 로컬 실행

### 3.1 사전 준비

- JDK 21
- Docker Desktop 또는 Docker Engine + Compose v2
- 사용 가능한 `8080`, `5432`, `6379` 포트

PowerShell에서 저장소를 받은 뒤 실행한다.

```powershell
cd backend
Copy-Item .env.example .env
```

`backend/.env`에서 필요한 AI·AWS 값을 채운다. 단순 API와 DB 기능만 확인한다면
`PUSH_ENABLED=false`, `GEMINI_DIRECT_MEDIA_ENABLED=false`로 두고 외부 AI 키를
비워 둘 수 있지만, AI 전화·게시글 분석·리포트 생성은 관련 키가 반드시 필요하다.

```powershell
docker compose --env-file .env -f compose.local.yml up -d
docker compose --env-file .env -f compose.local.yml ps
.\gradlew.bat clean test
.\gradlew.bat bootRun --args='--spring.profiles.active=local'
```

정상 확인 주소:

- Health: `http://localhost:8080/actuator/health`
- Swagger UI: `http://localhost:8080/swagger-ui.html`
- OpenAPI JSON: `http://localhost:8080/v3/api-docs`

Spring Boot 기동 시 Flyway가 `backend/src/main/resources/db/migration/`의
`V1`부터 최신 버전까지 순서대로 적용한다. Hibernate는 `ddl-auto=validate`로
스키마를 임의 생성하거나 수정하지 않는다.

```powershell
cd backend

```

release용 keystore와 속성 파일은 Git 밖에서 준비한다. 예시 형식은

기기에 설치하기 전에 API 주소가 HTTPS인지 확인한다.

## 6. 운영 수동 배포

운영 구성은 EC2에서 Nginx·Backend·Redis를 Docker Compose로 실행하고,
PostgreSQL은 Private Subnet의 RDS를 사용한다. 저장소 루트에서 실행한다.

```bash
cp infrastructure/production/.env.example infrastructure/production/.env
docker compose --env-file infrastructure/production/.env \
  -f infrastructure/production/compose.prod.yml config
docker compose --env-file infrastructure/production/.env \
  -f infrastructure/production/compose.prod.yml build backend
docker compose --env-file infrastructure/production/.env \
  -f infrastructure/production/compose.prod.yml up -d
docker compose --env-file infrastructure/production/.env \
  -f infrastructure/production/compose.prod.yml ps
```

외부 점검:

```bash
sh infrastructure/production/scripts/health-check.sh \
  https://api.familink360.com/actuator/health
```

정상 응답은 `{"status":"UP"}`이다.

## 7. Jenkins 자동 배포

1. `main` 병합 시 테스트와 BootJar 빌드를 실행한다.
2. Git Commit SHA로 Backend Docker 이미지를 태깅한다.
3. 개인 AWS 계정 ECR의 `familink-backend`로 Push한다.
4. Jenkins가 AWS SSM으로 운영 EC2에 배포 명령을 전달한다.
5. 운영 EC2는 새 이미지를 Pull하고 Backend 컨테이너만 교체한다.
6. 내부·외부 health check를 수행한다.
7. 실패하면 직전 이미지로 자동 rollback한다.

운영 EC2의 기본 저장소 경로:

```text
/home/ssm-user/S15P11B104
```

수동으로 동일 배포 스크립트를 호출할 때:

```bash
APP_ROOT=/home/ssm-user/S15P11B104 \
  bash /home/ssm-user/S15P11B104/infrastructure/production/scripts/deploy.sh \
  <40자리-GIT_COMMIT_SHA>
```

## 8. DB 접속과 IntelliJ 설정

RDS는 Public access가 꺼져 있으므로 PC에서 직접 Endpoint로 접속하지 않는다.
AWS SSM 포트포워딩을 먼저 연다.

```powershell
aws ssm start-session `
  --region ap-northeast-2 `
  --target <운영_EC2_INSTANCE_ID> `
  --document-name AWS-StartPortForwardingSessionToRemoteHost `
  --parameters '{"host":["<RDS_ENDPOINT>"],"portNumber":["5432"],"localPortNumber":["15432"]}'
```

이 터미널을 닫지 않은 상태에서 IntelliJ Database에 다음 값을 등록한다.

| 항목 | 값 |
|---|---|
| DBMS | PostgreSQL |
| Host | `localhost` |
| Port | `15432` |
| Database | `s15p11b104` |
| User | 운영 `DB_USERNAME` |
| Password | 운영 `DB_PASSWORD` |
| SSL | SSM 터널 구간에서는 기본 설정 사용 |

`Connection refused`이면 먼저 SSM 터널 터미널이 살아 있는지, `15432`가 LISTEN
상태인지, EC2 Managed node가 Online인지 확인한다.

### 8.1 제출 DB 덤프 복원

`exec/03_DB_덤프.sql`은 **비어 있는 PostgreSQL 16 데이터베이스**에 복원한다.
스키마와 Flyway 이력이 함께 들어 있으므로 별도로 Flyway를 먼저 실행하지 않는다.

```powershell
psql -h localhost -p 5432 -U postgres -d postgres `
  -c "CREATE DATABASE s15p11b104 WITH ENCODING 'UTF8';"
psql -h localhost -p 5432 -U postgres -d s15p11b104 `
  -f exec/03_DB_덤프.sql
```

복원 뒤 Backend를 기동하면 Flyway는 덤프에 기록된 `V1`~`V12` 이력을 검증하고
추가할 마이그레이션이 있을 때만 적용한다. 이미 같은 테이블이 있는 DB에 덤프를 실행하면
중복 오류가 발생하므로 기존 운영 DB에 실행하지 않는다.

복원 확인:

```sql
SELECT COUNT(*) FROM users;
SELECT COUNT(*) FROM family_groups;
SELECT COUNT(*) FROM posts;
SELECT COUNT(*) FROM calendar_events;
SELECT COUNT(*) FROM call_reports;
SELECT COUNT(*) FROM daily_reports;
```

제출 시점 선택 덤프의 예상 결과는 사용자 4명, 그룹 2개, 게시글 11개, 일정 2개이며
건별·일일 리포트는 각각 0개다.

## 10. 운영 점검

```bash
docker compose --env-file infrastructure/production/.env \
  -f infrastructure/production/compose.prod.yml ps
docker compose --env-file infrastructure/production/.env \
  -f infrastructure/production/compose.prod.yml logs --tail=200 nginx backend redis
curl -fsS https://api.familink360.com/actuator/health
```

운영에서는 `docker compose down -v`를 실행하지 않는다. `-v`는 Redis 영속
볼륨까지 제거하므로 로컬 데이터를 완전히 초기화할 때만 사용한다.
